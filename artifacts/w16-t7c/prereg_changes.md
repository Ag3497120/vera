# 事前登録後の試験の変更

## test_marker_safety（2026-10-06）
- 前: `redact(m + m)` の件数が 0（印を隙間なく 2 つ連ねる）。
- 後: `redact(m + " " + m)` の件数が 0（印を空白で連ねる）。
- 理由（実測）: 修正前の `ecde332` の既存の規則 `kv_secret` は、`gh_token`・`slack_token`・`kv_secret` の名前の直後の `:` を区切りとみなし、続く 8 文字以上を値として伏せる。`[REDACTED:gh_token:nfkc][REDACTED:gh_token:nfkc]` では `nfkc][REDACTED:gh_token:nfkc]` が値になり件数 1（`red_before.log` ではこの試験は印を作る実装が無くても `m + m` で赤だった）。印の名前を 4 文字以下にしても `]` の後に続く文字が 3 文字以上あれば当たる。回避は `REDACT_PATTERNS` の変更を要し許可外。
- 到達不能の根拠: 変形の段は区切り（空白・引用符）で分けたトークンの窓を印にするので、印の直後は必ず区切りか文末で、印同士が隙間なく接する出力は変形の段からは作られない。ただし既存の段が作る印（`[REDACTED:sk]` など）の直後に英数字が接する形は、従来どおり残り滓の規則が扱う（変更なし）。
- 弱めたかについて: 試験の厳しさは「印の直後に区切りが無い入力」を外した分だけ狭くなる。docs §15 の残る限界に開示した。
