# W10-fusion 設計書 — Vera と開いた重みの LLM の融合（2026-10-04、監査役。オーナーの指示: 層 0・1 から着手）

## 1. 目的
LLM が語彙・表現・一般知識を供給し、Vera が構造・根拠・記憶を握る。答えの各部分に **記録／証言／構成** の出所の型が付き、根拠の無い事実は言えない。Ollama／llama.cpp のランタイムで動く。到達が狭い間は「言える範囲」が狭い（安全側）。誤読 0・誤答 0 の原則は変えない。

## 2. 層

## 3. 高信頼の仕組み（全層に共通）
- 出力の各文を Vera が再読し、十字の各腕が **記録**（人の文書・ソブリンの昇格済み）／**証言**（LLM・生成コーパス）／**構成**（観測で作った閉包の外）のどれで埋まったかを型で付ける。事実の問いでは記録だけが答え（根拠の方針 A/C/E/D/B をそのまま適用）。
- LLM が補った語は配置に証言として入り、分布か人の確認で裏づけられたときだけ direct。
- 層 1 で縛れない文（読めない・割れる）は出さない。利用者には「構造が決まらないので言えない」と型で返す。

## 5. 層 0・1 の実装チケット（W10-f01）
- **入口**: `vera serve --backend ollama --model <name>`（OpenAI 互換 `/v1/chat/completions`）。1 ターンの流れ: (1) 入力を読む（質問の十字／平叙の十字）→ (2) 記録（文書・ソブリン）に当てる → (3) 層 1 の文法を作る → (4) Ollama へ（`format`/grammar つき）→ (5) 出力の各文を再読し、腕ごとに 記録／証言／構成 を付ける → (6) 根拠の方針を掛け、答え・確認の問い返し・棄権 のどれかを返す。応答の JSON に `vera: {reading, grammar_id, provenance[], outcome}` を付ける。
- **文法の作り方**（事前登録して書く）: 質問の十字の穴の型と、記録にある充填物の表記（NFKC 一致）、述語の形（記録の述語の辞書形＋許す語尾）、否定・時制の形。文法に無い語は出ない。読めない入力は文法を作らず、「構造が決まらない」の型で返す（LLM を自由に喋らせない設定を既定、`--free` で層 0 だけに落とせる）。
- **検査**: 記録にある事実の問い 50（答えが文法内で出る・出所が記録）、無い問い 50（棄権か確認の問い返し。LLM が勝手に答えない）、創作の依頼 20（構成で出る。事実の断定の形にならない）。誤答 0 が承認の条件。遅延（Vera の分と LLM の分を分けて測る）。
- **測定（監査役）**: B7 を層 0・1 経由で流し、生成だけの ANSWER 0・誤答 0。B2 の文書 QA の形。

## 6. 順序と依存
層 0・1（今）→ 層 2（LLM の証言の取り込み。W5-f の後）→ 層 3（W3-a6/W3-b6 で到達が伸び、訓練データが増えてから）。評価はすべて隠しバンクと影運用の三値で。

## 7. 層 4 の定義の見直し（2026-10-04 17:3x、オーナーの指摘を受けて）
- §2 の層 4「重みへの埋め込み（本学習）」は **採らない**。座標が重みに入ると「どの腕がどの記録に基づくか」が外から検査できなくなり、残る違いは訓練データだけ＝普通の LLM。第一目標（検査できる誤読 0・誤答 0、無重みの Vera）と矛盾する。本学習が要る理由（LoRA は埋め込みの幾何を変えられない・LLM の分布空間と配置の空間は同型でない・埋め込みだけ変えると回路が壊れる）は、そのまま「やるべきでない理由」でもある。
- 層 4 は **側路型** に定義し直す: 座標は配置の表（外、人が読める）に置いたまま、層 3 のモデルに「文脈中の語の座標（型・役割つきの枠・状態）を読む射影」を足す（LoRA と同じ枠で学習、数時間）。逆向きに、残差流への探針で未配置の語の候補座標を取り出し、**証言** として配置に入れる（分布か人の確認で direct）。Vera は無重みの検査器のまま、LLM は語彙と候補の供給源のまま。到達は配置の表の更新だけで伸び、再学習は要らない。
- 順序: 層 3 の最初のモデル → 層 2 → 層 4（側路）。層 4 の採否は層 3 がキラー分野の価値を示した後に決める。

## 8. オーナーの原則（2026-10-04 19:37:15 +0900）
1. **文書を読み込ませるだけで分野の独自 AI が組み上がる**: 取り込み時に配置に無い語を列挙し、LLM を経路づけ役として型・役割つきの枠・近い語を申告させ（証言）、その文書群自体を分布の腕として Vera が確認し、人は台帳をまとめて監査（任意）。配置は分野ごとに育ち、語彙が閉じた分野で Vera は単独になる。→ W10-f04 の第一の目的（取り込み時の候補補完）。出力時の候補補完はその上。
2. **根拠が無いことは言わない**: 不変。LLM の申告は常に証言の印。記録は文書の本文と人の確認だけ。
3. **日本語圏のみ**: 英語の配置・実現器は目標から外す。B1 の英語側は欠点として数えない（報告は続ける）。
4. **Vera 主導**: LLM は提案のみ。読む・決める・答える・棄権するは Vera の規則。LLM の差し替えで規則は変わらない。十字トークンの LoRA は「Vera の形式で候補を出す訓練」。
- 層 3 ＝ 候補補完（取り込み時・出力時）＋十字トークンの LoRA の両方。層 4 ＝ 重みを変えない融合（側路・学習なしの改変）。焼き込みは採らない（§7）。
