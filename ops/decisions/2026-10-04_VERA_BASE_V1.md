# Vera ベース v1 定義書（2026-10-04 19:47:18 +0900、監査役。オーナーの決定: 複文は v1、照応は v2）

## 0. 一文で
Vera の**構造の仕組み（アルゴリズム）**を検証つきで作り切り、ベース v1 として凍結する。凍結後はアルゴリズムを変えず、**データ**（配置、文書、証言の台帳、記憶、実現の形の表）だけで性能を伸ばす。LLM がベースモデルを固定して周辺とデータで伸びるのと同じ扱い。Vera は「LLM が外部ツールで補っていること（記憶・検索・検証・出所）を内部に取り込んだモデル」である。

## 1. 目標
- **第一目標**（オーナー、2026-10-04）: 一つのキラー分野で価値を示し、採用・開発の理由を一つ得る完成度で開発を完了する。
- **使い続けると明確に良くなる**（オーナー、同日夜）: 接続した当初より、使い続けることで最適化が進み、性能が上がったと利用者が感じられること。これはアルゴリズムの変更ではなく §5 のデータの成長で実現し、§7 の指標で測る。
- 不変の原則: 誤読 0・誤答 0。根拠が無いことは言わない。日本語圏のみ。Vera 主導（LLM は提案のみ）。文脈は重みでなく構造体に記録される。

## 3. 「以後アルゴリズムを変えない」の意味
- 変えてよいもの: 配置（r シリーズ、分野ごと・利用者ごと）、文書、証言の台帳と昇格、記憶、実現の形の表、閾値などの **設定値**（事前登録した範囲内）、LLM の後段（モデル・LoRA・側路）。
- 変えないもの: 規約の表、読解の規則と門、配置の判定の規則、根拠の方針、昇格の規則、再読の門、口の契約。
- 例外: 誤読・誤答が見つかったときの **狭める方向の修正**（棄権を増やす）だけは v1.x として許す。広げる修正は v2。
- 根拠: LLM と同じく、ベースが動かないから上に積める。利用者側の配置・台帳・記憶が、ベースの更新で無効にならない。

## 4. 受け入れ口（6 つ。契約を事前登録し、偽の後段と本物の後段の両方で検査）
| 口 | 契約（要点） |
|---|---|
| O1 候補の問い | 入力: 穴（型の候補、役割、述語、文脈の十字、文書の id）。出力: 候補 K 個（語、申告の型、申告の役割、根拠の種別）。問いの文面は Vera が作る。LLM は利用者の生の文を見ない設定を既定にできる |
| O2 証言の台帳 | 追記のみ。1 行＝（語、申告、出所＝モデル名／人、文脈、時刻、確認の状態、昇格の履歴）。読めるのは Vera だけ。人の監査は台帳の一覧でまとめて |
| O3 配置への流し込み | 台帳の確認済みの行を、生成コーパスと同じ形で builder に渡す。分野ごと・利用者ごとの配置を重ねられる（基底の r シリーズ＋上書きの層） |
| O4 再読の門 | LLM 由来の語・構造はすべてここを通る: 型の一致、再読一致、記録との非矛盾、同点棄権。通らなければ棄権の理由を型で返す |
| O5 座標の受け渡し | 配置の座標（型・枠・状態・分野）を LLM 側へ渡す直列化（十字トークン＝W10-f03 の形を採用）。プロンプト・文法・将来の側路の入力に共通 |
| O6 後段の差し替え | Ollama／OpenAI 互換 API／ローカルのアダプタ付きモデルを同じ呼び出しで。後段を替えても Vera の規則は変わらないことをテストで保証 |

**ブリッジ（学習なし、「Vera が無いと話せない」）**: LLM の入力は Vera が作り、出力は Vera が毎ターン記録から作る文法の中でしか復号できず、候補は O4 を通ったものだけ使われる。十字トークンの LoRA・側路・操舵は O5/O6 の外側の任意の強化で、無くてもブリッジは成立する。

## 5. 使い続けると良くなる仕組み（データの成長。アルゴリズムは不変）
| 成長するもの | どう育つか | 利用者が感じる変化 |
|---|---|---|
| 分野・利用者の配置（O3） | 読み込んだ文書の未配置語が証言→確認→direct に | 「前は読めなかった自分の分野の語が読める」。棄権が減り、記録からの答えが増える |
| 役割つきの枠 | 利用者の文書を分布の腕として CONFIRMED が増える | 曖昧だった に・で の文が読める |
| 証言の昇格 | 同じ候補が再読一致を重ねる／人が確認 | 答えの中の「証言」の印が減り「記録」が増える（§7 の証言率） |
| 記憶（ソブリン） | 決定・確認・名前が蓄積 | 聞き返しが減る。過去の決定を根拠つきで引ける |
| 実現の形の表 | 利用者の文体（丁寧体・語尾）の形が増える | 答えの文が自然になる |
| LLM 後段 | LoRA・側路は任意。口が同じなので差し替えで速く・正確に | 遅延が下がる |

重要: 利用者ごとの成長は **その利用者の配置・台帳・記憶** に閉じる（端末内で完結できる）。共有するのは人が選んだ分野の配置だけ。

## 7. 指標（使い続けて良くなったか）
- **被覆**: 利用者の記録に対する問いのうち、棄権せず記録から答えた割合（週ごと）。
- **証言率**: 答えの腕のうち LLM 由来の証言の割合（下がるほど単独に近い。分野で 5% 未満を「単独」と宣言）。
- **昇格数**: 台帳から direct／記録に上がった語・枠の数。
- **聞き返し率**: 確認の問い返しの割合（記憶が育てば下がる）。
- **誤読・誤答**: 常に 0（増えたら v1.x の狭める修正）。
- **遅延**: Vera の ms と後段の ms を分けて。
