# 知の層 — Vera をモデルとして人の色に染め、非公開・公開・レンタルで配り、対価が著者に戻る仕組み（設計書 v0.2（§13 追記 2026-10-05 13:36:40 +0900）、v0.1 2026-10-05 13:25:34 +0900、監査役。オーナーの指示で起草）

## 0. 核
**配るのは Vera というモデル（人の色に染まったデータ層つき）であり、指示文でも重みでもない。** Vera 本体（規則）はベース v1 で凍結され全員で同じ。人ごとの違いは層・枠・決定・台帳・文体・記憶という **データ** に閉じる。だから「モデルを選ぶ」のと同じ操作で「人（の知の層）を選ぶ」ことができ、答えの各文に **誰の記録か** が付く。

## 1. 用語
- **知の層（knowledge layer）**: 1 人（または 1 組織）の色に染まった Vera のデータ一式。版と署名を持つ。
- **装着（mount）**: 利用者の Vera に知の層を重ねること。外せる。
- **色（coloring）**: 層の中身の総称。語彙と型（配置の層）、確認済みの役割つきの枠、決定と理由の記録、手順・記録の文書、文体（実現の形の表）、記憶（名前つきソブリン）、仮定の台帳（昇格済みの分だけ）。
- **配り方**: 非公開（指名した相手に封筒つきで）、公開（誰でも装着できる）、レンタル（期間つき・サーバ側装着・利用の台帳が著者に戻る）。

## 2. 何ができて、何ができないか（嘘にならない線）
| できる | できない（出さない） |
|---|---|
| その人が **書いた・確認した** ことを、記録として根拠つきで答える（いつの記録かを必ず付ける） | その人が書いていないことを「その人ならこう言う」と断定する |
| その人の決定と理由を引く（「なぜそうしたか」の台帳） | 暗黙知・勘・好みの再現（記録に無いものは無い） |
| その人の語彙・枠・文体で読み、言う | 新しい状況の判断の代行（出せるのは **構成** の印つきの候補まで） |
| 記録の要素から組み立てた候補を **構成** と明示して出す | 本人の責任で答えること |
| 記録に無いときに「X の記録にはない」と言う | 黙って一般知識で埋めること（LLM の補いは証言の印つき） |
これは「クローン」ではなく **「その人の知の層を載せた Vera」** であり、名前もそう呼ぶ（製品名は別途）。

## 3. 層の中身（形式はすべて既存）
| 区画 | 形式（ベース v1） | 出所の印 |
|---|---|---|
| 語彙と型 | 配置の層（W10-f05 の `placement_layer`、基底 r9 を上書きしない） | `layer: person:<id>:<ver>` |
| 役割つきの枠 | 層の `role_frame`（確認済みのみ direct） | 同上 |
| 決定と理由 | `ops/decisions` の形（判断・理由・時刻・前提） | `record`（人の文書） |
| 文書 | 手順・記録・設計書（読込後の本文） | `record` |
| 文体 | 実現の形の表（W3-d1、追加のみ） | — |
| 記憶 | 名前つきソブリン（確認済みのみ） | `record`（human_confirmed） |
| 仮定の台帳 | W3-e2/W10-f04 の台帳のうち **昇格済み** の行だけ（未確認の仮定は配らない） | — |

## 4. 封筒（manifest）
```
author_id, display_name, public_key
version, created_at, supersedes
scope: private(<受け手の一覧>) | public | rental(<期間>, <条件>)
redaction: <除外の規則の版と、除外した件数>（雇用主の情報・個人情報・第三者の記録）
content_hashes: 各区画の sha256、台帳の連鎖の先頭 sha
signature: author の署名（封筒全体）
license, price, revocation_url
```
- 層に入れる前に **本人が篩を通す**（除外の候補を Vera が列挙し、人が確認。ここも台帳に残す）。
- 封筒の署名が無い層は「出所不明の層」として装着でき、答えの印は `person:unknown`。

## 5. 装着と優先順位・衝突
- 順: 基底 r9 → 分野の初期層（W12-c1）→ **人の層（複数可、装着順）** → 自分の層。下を上書きしない（K290）。
- **衝突**: 2 つの人の層が同じ語に別の型／同じ問いに別の記録を返すとき、混ぜない。読解では棄権（`LAYER_CONFLICT:<id1>,<id2>`）、問いでは **両方を並べて出所つきで提示** し、決めるのは利用者。
- 自分の層は人の層より上（自分の確認が優先）。ただし人の層の記録を「自分の記録」に書き換えることはできない（出所は変わらない）。

## 6. 出所の印
- `provenance` の腕と文に `person:<id>:<ver>` と `record_date`。答えの文には「（田中の記録 2026-03）」。
- 利用の台帳: どの層のどの記録が、いつ、どの問いで引かれたか（利用者側に残り、レンタルでは要約が著者に戻る。問いの本文は戻さない）。

## 7. 配り方と対価
| 形 | 配布物 | 対価 | 撤回 |
|---|---|---|---|
| 非公開 | 封筒つきの層ファイル（受け手の鍵で暗号化） | 契約 | 鍵の失効＋契約。ファイルの複製は止められない（§8） |
| 公開 | 封筒つきの層ファイル（署名のみ） | 寄付・名声・利用の台帳の公開 | 新版の発行と撤回の告知 |
| **レンタル** | **ファイルは渡さない。著者（または提供者）側の Vera に装着し、問い合わせの口だけを期間つきで開く** | 期間・問い数・引かれた記録の数に応じた対価（利用の台帳が根拠） | 口を閉じる。即時 |
レンタルが「モデルとして共有する」の本命。重みの API と同じ使い勝手で、中身は人の記録。

## 8. 保護の分析 — 最新のモデルは層を複製・再構成できるか（正直な答え）
1. **ファイルを渡した場合**: 層は人が読めるデータなので、リバースエンジニアリング以前に **複製は自明**。守るのは秘匿ではなく、署名（なりすましの防止）・契約・利用の台帳・透かし（`watermark.py` の系統: 配布ごとに語順や表記の変種を入れ、漏れた写しの出所を後から特定する）。重みと違い「取り出せないから安全」は使えない。
2. **問い合わせの口だけの場合（レンタル）**: 攻撃者は多くの問いを投げ、答えに含まれる記録を文単位で集められる。**答えた記録は漏れる**（これは本質で、どんな口でも同じ）。対策は、問いの上限・利用の台帳（異常な引き方の検出）・段階的な開示（要約の段と原文の段を分け、原文は上位の契約だけ）・透かし（答えの表記の変種で受け手を特定）。
3. **黒箱からの再構成**: 集めた答えから「同じ問いに同じ答えを返す層」を最新の LLM に作らせることはできる。**しかし作れるのは「言った分」だけ**で、言っていない記録・台帳の連鎖・著者の署名・いつの記録かの証明は作れない。偽の層は `person:unknown` にしかならず、Vera の印で区別がつく。価値の源泉（属性づけ・検証可能性・育ち）は複製できない。
4. **色の模倣**: LLM は文体や口癖は真似られるが、その人の **記録** を根拠に答えることはできない（真似た内容は証言の印になる）。Vera を介して読む限り、本物と模倣は印で見分けられる。
5. **結論**: 守るべきは「秘密」ではなく **「誰の記録かの証明」と「撤回できること」**。この 2 つは重みの共有では得られず、データの層でだけ得られる。だから設計の中心は暗号化ではなく、署名・連鎖・台帳・透かし・レンタルの口。

## 9. ハーネス（IDE・Cleanroom）での使われ方
- モデル選択の横に「知の層」の選択（複数）。装着中の層の一覧と版。
- エージェントが行動する前に層へ **自動で問い合わせ**（「この種の変更で X はどう決めたか」）。記録があれば提示、無ければ「X の記録にない」。影運用（W8-shadow-2）の経路と同じ。
- 各回答の文に誰の層からかの印（Cleanroom の ［記］ の横に `person:`）。
- **AGENTS.md／CLAUDE.md への投影**: 層から派生物を書き出す（各行に出所のコメント）。Vera の無い環境でも使え、Vera があれば一歩進んだ使い方になる。正本は層。

## 10. 評価（偽れない評判）
- 引かれた記録の数、利用者の決定で採用された数、矛盾が出た数、仮定が記録へ昇格した数（層の成熟）。星の評価は置かない。
- 層ごとの `assumption_rate`・`abstain_rate` の推移（装着して仮定が減ったか）。

## 12. 未決（オーナーの判断）
- 層に入れてよい記録の既定（本人が書いたものだけか、本人が確認した他者の記録も含むか）。
- レンタルの対価の単位（期間／問い数／引かれた記録数）。
- 公開層の品質の最低線（例: 署名あり・除外の篩を通過・assumption_rate の公開）。
- 「構成（閉包の外）」の候補を人の層から出すことを既定で許すか（既定はオフを提案: 本人の記録に無い組み合わせは、本人の名で出すべきでない）。

## 13. 私的層と知の層の分離 — 個人情報を漏らさずに「その人の頭の中の操作」を配る（v0.2 追記）
### 13.1 二つの層
| | 私的層（private） | 知の層（shareable） |
|---|---|---|
| 中身 | 文書の本文、事実の記録（誰が・いつ・どこで・何を）、名前・識別子・場所・金額、仮定の台帳の全行、記憶の全部 | **操作の知**: 手順の十字（条件 → 行動 → 確認）、決定の規則（どういう場合に何を優先したか）、検証の型（何を確かめてから進むか）、語彙と型（分野の層）、確認済みの役割つきの枠、文体の表、用語の定義文 |
| 出所の印 | `record`（本人にだけ見える） | `person:<id>` の `procedure`／`rule`／`check`／`lexicon` |
| 持ち出し | **決して出ない**（書き出しの道具が読まない。T-isolation と同じ機械の検査） | 封筒つきで配れる |
「その人の頭の中」とは、何を知っているか（事実）ではなく **どう読み・どう決め・どう確かめるか（操作）** であり、後者は本人の私的な事実を含まずに表せる。

### 13.2 分離の機械（Vera の十字がそのまま篩になる）
1. **型による篩**: 知の層へ写すとき、十字の充填物のうち PERSON・IDENTIFIER・PLACE（固有）・TIME（特定の日付）・QUANTITY（金額など）は **型つきの穴** に置き換える（W10-f04 の穴の形）。「田中に 3 月 5 日に見積書を渡す前に単価を確認した」→「[人] に [時] に見積書を渡す前に単価を確認する」。手順と検査の構造は残り、事実は消える。
2. **一般化の規則**: 1 件の出来事（記録）は出さない。**同じ構造が k 回以上**（既定 k=3、出所の異なる記録で）現れた手順・規則・検査だけを知の層に写す（独立出現の基準＝語彙層と同じ）。1 回しか起きていないことは事実であって操作ではない。
3. **語彙の篩**: 私的な文書にしか出ない語（出所 < k）は語彙層に写さない。公開コーパスか複数の文書で確認された語だけ。
4. **決定の記録の抽象化**: `ops/decisions` の形から、具体的な対象（案件名・人名）を穴にし、「判断の型」（何と何が対立したとき何を優先したか、理由の型）だけを写す。
5. **人の確認**: 書き出しの前に、Vera が「私的層にしか無い充填物」「k 未満の構造」「名前・識別子」を全部列挙し、本人が確認（台帳に残す）。既定は **出さない側**（列挙に入ったものは本人が明示的に許可しない限り穴のまま）。
6. **再識別の検査**: 書き出した知の層に対して、私的層の事実を問う（誰・いつ・どこ・いくら）。**すべて棄権** することを機械で確かめてから封筒に署名する（通らなければ書き出せない）。

### 13.3 使い勝手（利用者から見た「その人の AI」）
- 装着した知の層は、利用者の **自分の事実** に対して、その人の操作（手順・規則・検査・語彙・文体）を掛ける。「田中の層を載せると、自分の案件に田中の確認の順番と判断の型が効く」。田中の案件の中身は一切見えない。
- 答えの印は `person:田中:procedure`（操作の出所）と `record`（利用者自身の事実）に分かれる。混ざらない。

### 13.4 サーバー側（レンタル）での抽出への正直な答え（§8 の補足）
- 利用者が出力を集めて再構成できるのは、**答えた操作の構造**（手順・規則・語彙）まで。問いを尽くせば知の層の **答えられる部分はほぼ全部** 復元できる（人の助言と同じで、話したことは持ち帰れる）。これは防げないと認めた上で、(a) 私的層は口の向こうに無い（復元の対象にそもそも入らない）、(b) 署名・連鎖・「いつの」証明は復元できず、復元物は `person:unknown`、(c) 透かし（答えの表記の変種）で流出の受け手を特定、(d) 問いの上限と段階的開示で速度を落とす、を対策とする。
- つまり **「知は漏れうるが、個人情報は構造的に漏れず、本人の名はなりすませない」** が到達できる線。

### 13.5 開発中に育てながら使える印象のために
- 候補 1〜5 の製品はすべて、初日から **私的層と知の層の 2 つを持った状態** で配る（初期は両方とも初期搭載の層だけ）。育ちの指標（仮定率・棄権率・層の語数・昇格数）を常に見せ、「自分の層が育っている」と「知の層として配れる部分が増えている」を分けて表示する。
- 知の層の書き出しは最初から使える（中身が小さくても）。育てながら配る、を体験の既定にする。
