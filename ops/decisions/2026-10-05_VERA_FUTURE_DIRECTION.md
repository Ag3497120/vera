## 1. 結論

1. **LLM と「読む・答える・書く」能力で競う道は閉じています。**
   - いまの経路と物差しでは、Vera の上乗せが測れません。W14-bench run1 では、Vera strict が全項目で「常に棄権」と同じ、Vera 既定が全項目で素の 4B と同じでした（O）。
   - 規則で一般の日本語を読む方式は、8 月と 10 月の作り方の違う 2 世代で、同じ天井に当たっています（Cyc・規則翻訳・KNP→KWJA と同じ道筋）。
2. **伸ばすべきなのは「能力」ではなく「役目」です。** LLM が広がるほど価値が上がる役目が 3 つあります。
   - **審判**: 生成した者とは独立に、毎回同じ判定を出す。
   - **記録係**: 誰が言ったか、つまり人の記録か AI の証言かを、混ぜずに残す。
   - **物差し**: 他人が信用できる測り方を持つ。
   どれも「LLM が賢くなっても、自分の出力を自分で記録に昇格させてはいけない」という職務分離に根があるので、モデルが進歩しても消えません。
3. **Vera の読解器が役に立つのは、書き手を縛れる文だけです。** 2026 年に最も縛りやすい書き手は、エージェント（LLM）自身と、ルールを書く人です。開いた日本語ではありません。
4. **順位**
   - ① **AI の仕事の審判と記録（日本語）**。まず自分の艦隊で使う。
   - ② **物差しと方法論を外に出す**。
   - ③ **読解器を伸ばすかどうかの決着試験**。不変条件の判断が要る。
   - 知の層・提案者と受理者は、安い撤退試験つきの長期の賭けにとどめます。
5. **キラー分野の候補は「日本語で行われる AI エージェントの仕事の、信頼できる記録と判定」です。** 記録上、Vera の原則が実際に使われ、役に立ったのはここだけです。オーナー自身が最大の利用者でもあります。ただし外部の需要は未確認なので、30 日で外の人に当てて確かめます。
6. **誤答 0 は、いまも破れています（再現）。** 「〜てはならない」から「はい」、「明日東京」、「叔」です。分母のない「誤読0・誤答0」は外に出さないでください。
7. **次の 30 日は、新しい能力を足さず、決着をつけるための測定と衛生に使ってください。** 目標の言い直しは判定日に限ります。記録では 68 時間で 8 回言い直されていて、艦隊はそのたびの方向をそのまま増幅しました。

- **律速は実装の速さではなく、決定の安定です。**

## 3. LLM が支配する中で Vera が立てる場所 — 原理

外部調査（R1〜R6）を一行にまとめるとこうなります。**2025〜26 年に記号的な系が生き残った場所は、ほぼすべて「LLM が作り、記号系が検査する」構図で、記号系が読み手・作り手として勝った例は見つからない。** 例: Lean・AlphaProof、AWS Automated Reasoning checks、CodeQL＋Copilot Autofix、text-to-SQL。

そのうえで、決定的で重みを持たない部品が LLM の進歩で負けない理由は、スコアではなく性質にしかありません。

| 性質 | なぜ LLM の進歩で消えないか | 証拠（C） |
|---|---|---|
| 生成者からの独立（職務分離） | 自分で作ったものを自分で承認しないという原則は、能力では置き換わらない | エージェントは完了を、実際より 28.7〜37.9pt 多く申告する（R5、arXiv 2609.29921） |
| 来歴を混ぜないこと | LLM による記憶の統合は出所を消す（provenance laundering）。重み付けによる防御は効かなかった | R1・R2・R4（arXiv 2607.29167、2608.21230） |
| 決定性・再現性 | モデルを更新すれば判定が変わる。規範の基準器には、版ごとに揺れないものが要る | 多言語での LLM 判定の一致度 κ≈0.3、LLM 判定器への注入の成功率は最大 73.8%（R1） |
| 書き手を縛れる文での完全な読み | 制御言語（STE）は書き手を規則に従わせられる場所で生き残った。ACE は学術にとどまった | R6 L8 |

逆に、**負ける場所**は明確です。汎用の日本語読解・QA・要約・翻訳・チャット、法令 QA（政府が LLM で内製し OSS 化）、汎用の幻覚検出 API（1,000 文字あたり約 $0.00017 で大手が束ねて提供）、記憶ストア単体（Mem0・Letta・Zep・各社の内蔵記憶）、オーケストレーション、知の層のマーケットです。

**日本固有の注意**（R3・R5）
- 日本の規制は「誤答ゼロ」も「決定性」も求めていません。金融庁は「絶対に誤らない」水準を不適切としています。
- 法務省のガイドライン（2026-08-21）は、正確性を保証するかのような表示を慎むよう求めています。
- 売り物になるのは「誤答ゼロ」ではなく、**「根拠が示せないものは出さない」「人の確認の手間を減らす」「同じ入力には同じ判定」** です。

## 4. 伸ばす方向（順位）

### ① AI の仕事の審判と記録（日本語）— まず自分の艦隊で

- **何か**
  - エージェントの作業について、**誰が何を言い、何が証拠で確かめられ、誰が承認したか** を、追記のみ・番号つきで残します。
  - エージェントの「完了した」「テストが通った」「W3-f1 を直した」という申告を、**証言** として受け取ります。
  - 実際の出来事（終了コード、追加されたテスト、変更されたファイルのハッシュ、受入コマンドの再実行）と照合し、一致したものだけを **記録** に上げます。
  - 一致しない、または証拠の無い申告は、型つきで差し戻します。
  - 人の決定は逐語で残し、指揮者の聞き返しにはその台帳から答えます。台帳に無ければ人に聞きます。
- **核は読解器に依存しません。** 契約（出所の型・昇格の規則・型つき棄権）と台帳で成り立ちます。
- **日本語の読解器の役割は、書き手を縛れる部分に限ります。**
  - エージェントに、完了の申告や決定の要約を Vera が読める文型（今の時点で誤読 0 で読める 2 型など）で書かせ、Vera がそれを十字に読んで台帳の出来事と照合します。
  - これは **JSON の構造化出力と正規表現を対照に置いて** 比べ、上乗せがあるときだけ残します。上乗せが無ければ、「読解器は不要」という結論も立派な結果として記録します。
- **なぜここか**
  1. Vera の原則が実際に役立った記録があるのはここだけです（9 月の 505 件・引用 175 回）。
  2. オーナーが最大の利用者で、需要の一次資料が毎日生まれています（中断が残らない、最新が引けない、25.8 時間の事後補填）。
  3. 書き手（エージェント）を縛れるので、読解の範囲の狭さが弱点になりにくいです。
  4. 職務分離は LLM の進歩で消えません（§3）。
  5. 不変条件を変えずに今すぐ試せます。base v1 のままで、日本語の規則と記録を扱えます。
- **正直な弱点**
  - hook・台帳・記憶は汎用品です（Hookify、Entire、各社の内蔵記憶）。製品として外に売れる根拠は、まだ 0 です。
  - 反論役 3 体は「社内の基盤としてなら残る」と判定しました。外部の需要は、§7 の外部接触で確かめるまで仮説です。
  - 候補の需要は、日本企業の AI 利用の内部統制（AI 事業者ガイドラインの入出力・判断根拠のログ、稟議・承認の文化）と、規制業種のエージェント運用です。どちらも (I) で、聞いていません。
- **撤退条件**（事前登録）
  - 14 日で、記録が自分の作業で一度も引用されなければ、hook の自動記録を止めます。
  - 完了申告の照合で、Vera の読解が JSON と正規表現に対して上乗せ 0 なら、読解器をこの役から外します（台帳と契約は残す）。
  - 30 日以内に外部の 5 者に話し、関心が 0 なら製品化はしません（自分の基盤として残す）。

### ② 物差しと方法論を外に出す

- **何か**
  1. **W14-bench run1 を公開します。** 人の採点（MIXED の行）と「常に棄権」の列をつけ、Vera が負けている数字もそのまま出します。
  2. **日本語の「版と棄権つき根拠 QA」の物差しを作ります。** 人が書いた時点つきの文書（e-Gov 法令 API v2、自治体の例規）で 100 問を作り、決定的に採点し、誤答には罰点をつけます。問いは人が書き、gpt-6-luna には書かせません。Vera はその上の基準線の一つに過ぎません。
  3. **艦隊開発の事例報告**（否定的な結果を含む）を書きます。
     - 自作のデータで満点、隠しバンクで 0 が 3 回出たこと。
     - 攻撃波の命中が減らなかったこと。
     - 受入を機械で判定できる仕事だけが残ったこと。
     - 別系統の分離が 1.5 日で崩れたこと。
- **なぜか**
  - 物差しを持つ側の位置は、モデルが良くなるほど価値が上がります。
  - 一人の作者が信用を得られる、ほぼ唯一の配布手段でもあります（J2・J5、C）。
  - 日本語の既存の物差しには、版の観点と決定的な採点の両方を持つものがありません（C）。
  - オーナーの最も強い資産（測定の規律）を、そのまま外に出せます。
- **正直な弱点**
  - これは「Vera の能力」を示す道ではありません。Vera は「常に棄権」に近い位置に出る見込みです。
  - 第三者に使われなければ価値は小さいです。
- **最初の一手**
  - 河原研・LLM-jp の評価 WG に、同じ物差しが既にないかを確かめます。あれば合流します。
  - 2 人目の人の採点者を確保します（有償でもよく、エージェントでは代えません）。
- **撤退条件**: 試作 100 問で採点者の一致度が κ<0.7 なら作り直すか止めます。公開から 6 か月で第三者の実行が 0 件なら、保守をやめます。

### ③ 読解器を伸ばすかどうかの決着試験（オーナーの判断が要る）

- **何か**
  - 「データで育つ」を、初めて正しい形で試します。データは LLM の生成物ではなく、**人が書いた文と人の確認** に限ります。
  - 前提として、人が確認した行を、読解の判断点に実際に届かせる必要があります。今は、人の行が `_is_person_phrase` などの判断に届かず、層は基底の決定より下に置かれています（K290）。
- **今ある兆し（弱い）**
  - 人の確認 16 件で、統制した文の読める数が 20/102 から 58/102 になりました。
  - ただし、増えた分は確認した語が再び出た分で、一般化は示せていません。オーナーの実際の運用文では 2/55 のまま、条文は 0/100 のままでした（C、C1 の監査の指摘を採用）。
- **不変条件との関係（隠さずに書きます）**
  - これは「アルゴリズムを凍結し、データだけで育てる」の **読み替えではなく変更** です。判断点が人の行を引くようにするのは、アルゴリズムの変更だからです（codex の監査の指摘を採用）。
  - 一方で、オーナー自身の凍結条件（VERA_BASE_V1 §6 の 4(a)(b)）はまだ満たされていません。したがって **「まだ凍結しない」はオーナーのルールどおり** です。
  - 決めていただくのは「何を凍結するか」です（§6）。
- **試験**（事前登録、2〜3 週）
  - オーナーが作業文とルール文を 150 文書きます。半分は今の書き方、半分は統制した書き方です。
  - 確認は 50 行以下とし、確認する語は訓練の分割から選びます。
  - 試験は 2 本です。棄権の原因になる名詞が確認語と重ならない集合と、確認語の一覧を知らずに書かれた実際の文です。
  - 指標は「確認 1 件あたりに新しく読めた文」と「1pt 上げるのにかかったオーナーの分数」です。
- **撤退条件**: 実際の文での傾きがほぼ 0、または直せない誤読が出たら、v1 での「データで育つ」を取り下げます。そのときは Vera を、**範囲が固定された受理器** として凍結します（①と②はそれでも成り立ちます）。

### 長期の賭け（安い撤退試験だけ）

- **提案者と受理者**
  - 内容: KWJA や LLM が読みを提案し、Vera が局所の検査だけで受理します。
  - 現状、検証器は実質「読み直しの門」で、外すと誤った提案 156 件のうち 29 件が通ります（C）。
  - 撤退試験: 読み直しを使わない受理表で、誤提案の 99% 以上を棄却できるかを 1〜2 日で試します。通らなければ書庫に入れます。通らない見込みが大きいです。
- **共有できる知の層**
  - ③に合格した層だけを、既存の形式（Agent Skills・AGENTS.md・textlint の辞書）に書き出して配ります。
  - マーケット・レンタル・対価は、需要の証拠が無く、歴史的にも誘因の問題で失敗しているので、後に回します。

## 9. 草稿・監査と私の見方が違う点（I）

- **私は、読解器ではなく「契約と台帳」を Vera の中心に置きます。** Vera の名前で守るべきものは、「十字を読む力」ではなく「人の記録と AI の証言を混ぜない、決定的な審判」だと考えます。読解器は、書き手を縛れるところで、その審判を日本語の文にも広げる部品です。
- **初見の印象として、問題は能力より運営にあります。** 決定の言い直しと、記録にオーナーの声が無いことです。これは①の記録の層でまず自分が直すべきことで、同時に①の需要の証拠でもあります。
- **報告群と判定者は、法令・規程を最初の分野に推しすぎていました**（外部調査の「空白」から需要を推した）。反論役が既存の製品の多さで崩したのが正しいと見ます。
- **偏りの自己申告。** この結論も Claude 系の監査役の目です。否定寄りに傾く癖を、codex の監査で一部補正しました。それでも、オーナーの長期の像（Vera を使うほど育つモデル）を過小評価している可能性があります。③はそれを公平に試すために残しています。
