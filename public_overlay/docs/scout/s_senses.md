# Scout: senses, aliases, definitions, and out-of-frame terms

## Scope and observed wiring

The shelf is a finite lexical index, not a predicate-argument store. It can name page titles, redirects, parenthetical sense candidates, domain tags, lead tokens, and one lead sentence. That can make a surface recognizable and expose ambiguity. It does not itself say which argument role a word fills or license a fact.

- `verantyx/sense_split.py:200-212,237-298` has `parse_parenthetical(title: str) -> Optional[Tuple[str, str]]` and `build(pages: Iterable[Tuple[str, str]], *, aliases: Optional[Dict[str, str]] = None, extra_titles: Optional[Iterable[str]] = None) -> Dict[str, List[Dict[str, Any]]]`. - `verantyx/meaning_descent.py:91-123,157-183,206-317` has `first_sentence(lead: str) -> str`, `canonical(term: str, aliases: Optional[Dict[str, str]]) -> str`, `lookup_def(unit: str, defs: Optional[Dict[str, str]], aliases: Optional[Dict[str, str]]) -> Tuple[Optional[str], str]`, `grounding_of(result: Dict[str, Any]) -> str`, and `descend(term: str, *, lattice: Lattice, defs: Optional[Dict[str, str]], aliases: Optional[Dict[str, str]], depth: int = 2, _seen: Optional[Set[str]] = None) -> Dict[str, Any]`. ## What blocks the semantic connection

- There is no import or call from the semantic modules to `meaning_assets`, `sense_split`, `meaning_descent`, or `coverage`. `Vera.__init__(..., mode: str = 'legacy', ...)` at `verantyx/one.py:66-99` sets up the semantic retriever when `mode == 'semantic'`; `Vera.ask(self, question_text: str, *, query: question.Query | None = None, mode: str | None = None, **engine_kwargs: Any) -> dict` at `:779-795` dispatches directly to `_ask_semantic`. That method calls `question.read_semantic(text)`, then `semantic.answer`; its document branch uses `semantic_reader.document_view`, and its no-Bot branch uses `semantic_retrieve.Retriever` (`:352-418`). The older `general` definition door calls `descend` at `one.py:850-866`, but that branch is not the semantic route.
- `semantic_reader.document_view(documents, *, sovereigns=None, family='document')` at `verantyx/semantic_reader.py:253-273` turns supported sentence frames into source-bound `Clause`s and preserves unsupported text as `Unread`; question parsing is similarly bounded (`read_request(text, budget=Budget())` at `:413-470`). In `semantic.py:27-68`, a mandatory unread request or source returns a typed refusal before any answer. A lexical lookup can expose a word, but it cannot supply a missing predicate frame or turn an unparsed sentence into a supported clause.
- The semantic IR has `Pattern(predicate, roles, ...)`, source-spanned `Role`/`Clause`, and `View(sources, clauses, unread, ...)` (`verantyx/semantic_ir.py:78-123,274-303`). Entity values are presently strings (`:306-319`); `semantic_execute.bind(pattern: Pattern, clause: Clause, initial: dict | None = None, *, opposite: bool = False) -> dict | None` uses exact role matching after optional `Nominal` head checks (`semantic_execute.py:29-66`). A lexical mapping needs a typed, auditable handoff; a free string substitution is indistinguishable from an unsupported guess.
- The semantic path deliberately has an independent gate: `semantic.answer(request, views, *, budget=Budget(), trace=())` runs `Producer` and then `Checker.gate` (`semantic.py:27-59`). `license_clause` requires exact original source spans and literal role licensing (`semantic_verify.py:264-282`); proof replay rematches the plan against licensed source clauses (`:673-765`). If a producer alone canonicalizes a surface, replay must either independently reproduce and validate that mapping or reject it. Definitions and generated descent text cannot be inserted as `Clause`, `ProofNode`, source citation, or an `ANSWER`.
- Routing also keys on surface strings. `semantic_route.pattern_anchors()` reads literal role strings and `LeafTree` indexes clause terms (`semantic_route.py:52-80,84-105`). An alias-aware route must include the observed form and any safe canonical form, and preserve the current whole-view fallback for ambiguous/common terms. Narrowing on a guessed sense could hide an opposing source.

## Minimal typed, non-voting design

Introduce one shared read-only lookup contract, consumed by adapters rather than by the proof store:

```text
SenseOption(core: str, domain_tag: str)
LexicalResolution(
    surface: str, span: Span | None, alias_target: str | None,
    options: tuple[SenseOption, ...], selected_core: str | None,
    status: RESOLVED | RESOLVED_PRIMARY | AMBIGUOUS | NOT_FOUND | ASSET_MISSING,
    source_ref: str,
)
lookup(surface: str, context_tokens: tuple[str, ...] = ()) -> LexicalResolution
```

The lookup reads keyed `aliases()`/`senses()` access and only requests a definition when a caller explicitly asks for a constructed gloss. Cross exactly these lexical fields: input surface and its original span; bounded context tokens used only for sense selection; one-hop alias target; candidate `(core, domain_tag)` pairs; resolution status; and a source/index identifier. Do not cross lead prose, co-occurrence counts, a generated definition sentence, or a synthetic semantic clause.

For the semantic reader, attach each result to the matching request or source role span. Only a direct one-hop alias or a uniquely context-matched sense may normalize a role value, and the same immutable lookup must be applied to both request patterns and document clauses. Keep raw text and offsets for citation. Ambiguous, primary-only, missing, or asset-missing terms remain literal and produce a typed unresolved/abstention path; they are never converted to negation. The checker must replay the exact normalization from the pinned lexical map and validate its source reference before accepting a proof. The producer and checker still derive facts only from original `View.sources` spans.

For the conductor, pass the same `LexicalResolution` as a vocabulary annotation on the existing typed question/Reply or escalation path. It can expose the finite candidate list and say which spelling/redirect is indexed; an ambiguous term remains an explicit choice/escalation. It must not create a conductor `ALIAS` record, satisfy a POLICY, choose between project options, or answer factual questions from a gloss. `coverage.document_needed` can provide a separate typed missing-shelf suggestion. This keeps lexical lookup non-voting and avoids runtime learning.

## What remains testimony-only

The jawiki title/redirect/sense inventory is lexical testimony: it establishes that these strings and candidate titles occur in that snapshot, not that two strings are interchangeable in every context. `lead_tokens` and domain tags can help identify a candidate sense; they are not support for a semantic proposition. A lead sentence returned by `lookup_def` is testimony from the named jawiki page. It may be shown as a cited shelf quote in a separate lookup response, but it cannot be promoted to a semantic `Clause` or count toward a proof. `descend`'s assembled decomposition/gloss remains constructed output marked as such, never a source answer. Coverage ranks shelf proximity only; its score is not confidence, evidence weight, or a vote.

## Risks and first failure to measure

The first likely harmful failure is a false merge: an alias or homonym is normalized to the wrong entity and creates a source binding that the raw sentence did not support. Measure this first on independently labeled ambiguous/redirect pairs: false normalization rate, and the count of semantic `ANSWER`s newly enabled by normalization whose gold entity is different. Report recall of safe alias normalization separately; do not improve recall by relaxing the ambiguity rule. Other risks are stale/missing sidecars, `RESOLVED_PRIMARY` being mistaken for context resolution, the static `granularity.SPLITS` in coverage disagreeing with the attested lattice, large JSON/lattice load costs, and route fan-out or missed contradictions when aliases are not indexed consistently.

## Independent test plan

Create a small frozen gold sheet before running the resolver. Two annotators independently label raw, human-written question/source sentences with the intended entity, valid alias relation (if any), all plausible senses, whether context selects exactly one, and whether the sentence contains a supported semantic frame. Adjudicate disagreements without consulting `resolve`, `descend`, or the tested lookup output. Keep the raw sentence and expected answer/binding in the gold sheet; use a separately reviewed redirect list for alias targets. Include exact titles, one-hop redirects, alias chains, context selecting one sense, context matching multiple senses, no-context polysemy, disambiguation pages, unknown terms, missing assets, and a source clause whose unknown nominal must stay unread.

Run lexical precision/recall against those labels, then semantic integration comparisons with normalization enabled/disabled. For every returned answer, verify the cited raw spans and entity labels against the independent gold; count false answers separately from safe abstentions. Assert that ambiguity/missing assets never become negative answers, that generated glosses never appear as proof sources, and that an alias lookup cannot remove a contradictory source from the full evidence view. Measure conductor behavior separately: finite options surfaced, ambiguity escalated, and no shelf alias adopted as a testimony record. Freeze the gold and acceptance criteria before changing the implementation; do not use production sidecar output as its own oracle.

## Reach and local measurement

The reachable gain is lexical: make known titles and safe redirects available as a closed set, name competing senses instead of treating every unfamiliar surface as wholly opaque, and attach a shallow constructed unit gloss where the lattice and definition sidecar both have entries. In a semantic query this can help only when the surrounding predicate/role frame is already supported and the query/source term can be safely aligned. In a conductor question it can offer named spellings/options or explain that the term is ambiguous/missing. It does not add predicate-argument frames, infer definitions for missing titles, settle context-free homonyms safely, or turn encyclopedia prose into a sourced answer. There is no measured corpus coverage estimate for the semantic path here.

I ran one hand-built probe with the supplied empty corpus root and no sidecar reads. The synthetic lattice had 3 words, 8 slots, and 4 atoms; `descend("電荷密度", ...)` selected `電荷 + 密度`, returned 2 named units, and marked grounding `full`. A hand-written 2-sense `Delta` table with one context token returned `RESOLVED` to `Delta (river)` and retained the other candidate. A one-domain fake coverage store returned one `held: Delta` signal with score 2. These are plumbing observations on toy inputs only, not coverage or quality estimates. The real sidecar availability, false-normalization rate, and end-to-end semantic benefit remain unmeasured in this worktree.
