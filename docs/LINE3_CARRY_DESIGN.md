## 3. データモデル

### 3.1 用語

| 用語 | 定義 |
|---|---|
| 段 k | 0 = 黒（最小単位）、1 = 赤、2 = 青、…。段 k の単位は「段 k の要素」を席に置いた 1 つの立体十字（類＝1 状態） |
| 要素 | 席に置かれるもの。段 0 では語（その段＝RUN/WORD/CHAR の単位）、段 k≥1 では段 k−1 の閉じた単位のパック。**パックは下の段の十字にも置ける（C-5「扱える最小単位」）** |
| 単位 U | 段 k の 1 つの十字。状態は **開いている**（まだ受け取る）か **閉じた**（崩れて上の段へパックされた） |
| ソブリン S_k | 段 k の全単位（閉じた＋開いた）を台帳の順に並べた集まり（C-3）。黒のソブリン、赤のソブリン… |
| 出来事（occurrence） | (sid, 位置) = ある文に現れた 1 つの単位（V2 の既定の空間。同じ文の同じ単位は最初の 1 回だけ、L-302）。流れの最小の項目 |
| 範囲 scope(U) | U が**新しく**受け取った出来事の集合。段 0 では U に入った出来事、段 k≥1 では U の新しい要素（子のパック）の範囲の和 |
| パック P(U) | 閉じた U を圧縮した段 k+1 の要素（§3.3） |
| 前線 F | その時点で開いている全ての上の段の単位の「新しい要素」の和。過去の全ての出来事を重ならずに覆う（§3.4） |
| 持ち越し（carry） | 単位が開くときに写される前線の写し（不変のスナップショット）。案 2 の「コピー」 |

### 3.2 単位の中身（引き継ぎと新規の共存）

```
Unit U (段 k, 番号 j, id "U{k}:{j}")
  status        : open | closed
  carry         : CarrySnapshot id          # 開いた時の前線の写し（不変）
  new           : [element id, ...]          # 新しい要素（段0: 語, 段k: 子のパック）到着順
  active_inh    : [element id, ...]          # 持ち越しのうち、新しい出来事が触れて席に置かれたもの（印 inherited）
  dormant_inh   : carry の残り（席に置かれていない引き継ぎ。一覧として保持）
  scope         : [(sid, pos), ...]          # 新しい出来事だけ（台帳順）
  state         : 類（members: Flat の組, L, centres, score）= placement の Placement と同じ形
  admitted_upto : 最後に安定だった時の台帳の seq（N-05 の復元点）
```

**一つの十字の中で、新しい要素と引き継いだ要素は同じ席の並びに置かれる。区別は要素ごとの印 `origin ∈ {new, inherited}` で持つ。** 引き継いだ要素の「過去の数え」は U の中では一切使わない（条件 2、§3.5）。

### 3.3 パック（圧縮した状態）

```
Pack P = P(U)  (段 k+1 の要素, id "P{k+1}:{j}")
  unit        : "U{k}:{j}"                      # 降りる先（条件 1）
  own_occ     : scope(U)                        # 出所: 元の出来事（文と位置）
  own_sids    : scope(U) の sid の集合
  vocab       : U の新しい要素の語の和（段0: 新しい語; 段k: 子パックの vocab の和）。引き継いだ要素の語は入れない
  state       : U の類（members, L, centres, score, stop）           # 安定状態の全て（N-06）
  inherited   : active_inh(U)（U が触れて置いた古いパック。印 inherited、向き=過去への参照）
  carry_ref   : U.carry
  closed_by   : 崩した出来事（seq）と理由（"budget:max_states" など）, 予算の段
```

パックは「その単位の全ての要素を圧縮した、扱える最小単位」（C-5）。量（その要素が文に現れるか）は【M-1(c) ①】と同じ: **文が P を含む ⇔ その文の出来事の語が vocab(P) にある**（T8 の BundleTier の「語の文の和集合」と同じ規則）。ただし、どの単位の中で数えるときも、その単位の範囲の出来事だけで判定する（§3.5）。

### 3.4 前線と持ち越し（何をコピーするか）【推奨＝OP-1 (a)】

開いている単位を段ごとに O_0（今の黒）, O_1（今の赤）, …, O_D（最上段）とする（各段に開いた単位はちょうど 1 つ）。

```
F(k) = ⋃_{i=k+1..D} new(O_i)      # 段 k の単位が開く時に見える前線
```

- 段 0 の黒が閉じると、そのパックは O_1 の新しい要素になる。O_1 が閉じればそのパックは O_2 へ、…（繰り上がり）。だから前線は **過去の全ての出来事を重ならずに覆う**パックの集まりで、大きさは段の数×各段の容量（数十）にとどまる。
- **新しい単位 U が開くとき、F(k) の写しを carry として持つ**。これが案 2 の「パックされた圧縮された情報が隣にできた黒の十字にコピーされます」。どの段でも同じ（C-6「その青色も同じ流れを辿る」）。
- 写しの中のパックは最初は**眠っている**（席に置かない）。U に入った新しい出来事の語が vocab(e) にある引き継ぎ e は、その出来事と同じ群で席に入る（**起こす**、§4.2）。起きた e は U の中で、新しい出来事との共有だけを証拠に並ぶ。

なぜ眠らせるか: 新しい証拠と 1 つも共有しない要素は辺の重みが全て 0 で、どの席にも動ける。席に置くと同点の類が爆発する（T4b の原因と同じ）。触れたものだけを置けば、置いた引き継ぎには必ず辺がある。

### 3.5 単位の局所空間（証拠を数える場所）

単位 U の鍵・エネルギー・比率・問いの全ては、次の局所空間の上でだけ数える。

```
文:    sids(U) = scope(U) に出来事を持つ文（台帳順）
単位:  文 s の単位の列 units_U(s) = U の席の要素 x のうち s に「含まれる」もの、位置の順
        語 x: (s, pos) ∈ scope(U) で単位が x
        パック x（新・引き継ぎとも）: (s, pos) ∈ scope(U) の語が vocab(x) にある。位置はその最小
N_U = |sids(U)|,  n_U(x) = x を含む文の数,  n_U(x,y), p_U(x,y)（同じ位置は厳密比較でどちらにも数えない＝BundleTier と同じ）
r0_U(x) = n_U(x)/N_U,   E_Q,U(x) = r0_U(x) + Σ_q n_U(q,x)/N_U     # 【I-06】【N-01】
```

- **条件 2 はこの定義で構造的に守られる**: 引き継いだ要素の過去の文（範囲の外）は U の局所空間に入らない。引き継ぎは「U の新しい出来事に触れられた」回数だけで数えられる。
- 段ごとに、全単位の範囲は全ての出来事を**重ならずに分ける**（各出来事は段 0 でちょうど 1 つの黒に入り、各パックはちょうど 1 つの親の新しい要素になる）。だから一つの段の中で同じ出来事が 2 回証拠になることはない。
- 一つの文が 2 つの黒にまたがる（OP-2）と、またぐ前後の語の共有は段 0 では数えられず、その 2 つの黒のパックを並べた段 1 の局所空間で初めて見える（§4.6 の例）。

### 3.6 安定・不安定（既決の再利用）

単位 U に項目（§4.1）を入れる 1 回の受け入れ:
1. 局所空間に新しい出来事を足す（重みが変わりうる）。
2. 今の類を新しい重みで落ち着かせ直す（L-71、全メンバーから）。
3. 新しい要素の群（新しい語＋起こした引き継ぎ、または子のパック＋起こした引き継ぎ）を同時に挿入し（L-64）、落ち着かせる（L-71）。
4. 2・3 のどこかで予算（その段の予算の段、L-73/L-76）を超えたら **不安定**: 直前の安定（復元点、§4.1 の境界）を復元して U を閉じる【N-05】【N-09】。超えなければ受け入れを確定。

不安定の意味は **OP-3** に上げる（推奨は上のとおり「予算内で不動点の類に落ち着けない」だけ。既決の L-72 の唯一の崩れ方）。容量は予算の段に依存する（T4c で既知）。予算の段は台帳に記録し、段ごとに測る（§6）。

### 3.7 台帳（条件 3）

`line3.carry.ledger.v1`、1 行 1 出来事の JSONL（正準 JSON、L-319）。

```
header: {format, data_sha256, tier, unit_filter, order: {kind: file|shuffle|reverse, seed}, order_sha256 (sid 列の sha),
         build_level, admission (OP-2 の選択), copy (OP-1 の選択), instability (OP-3 の選択), code_commit}

```

## 4. 構築の手順（決定論的アルゴリズム）

### 4.1 項目と境界

- 流れ: 台帳の順の文 s_0, s_1, …（既定はデータファイルの行順＝sha の順、L-321）。各文の出来事は文の語順。
- 段 0 の項目 = 1 つの出来事（語）。境界 = 文の終わり。
- 段 k≥1 の項目 = 閉じた子のパック 1 つ。境界 = 項目ごと。
- 復元点: 【推奨＝OP-2 (b)】黒は**文の境界でだけ閉じる**: 文の途中の語で崩れたら、その文の前の境界の状態に戻して閉じ、その文を丸ごと次の黒へ送る。新しい黒でもその文が入りきらない（空の黒で崩れる）ときだけ、文をそこで分ける（分けた点を台帳に記録）。§2 の測定では WORD の約 3/4、RUN の約 1/4 の文がこの分割を受ける。

### 4.2 擬似コード

```
build(stream, tier, level):
  O = [new_unit(0, carry=∅)]                           # O[k] = 段 k の開いた単位
  for s in stream:                                     # 台帳順
    admit_sentence(O, s)

admit_sentence(O, s):
  U = O[0]; mark = checkpoint(U)                       # 文の境界（復元点）
  for occ in occurrences(s):                           # 語順。既に置かれた語は範囲だけ増える
    ok = admit(U, occ)                                 # §3.6 の 1〜3
    if not ok:
      if U.has_items_before(mark):                     # この黒に前の文がある
        restore(U, mark); close_and_carry(O, 0)        # N-05: 境界へ戻して閉じる
        U = O[0]; mark = checkpoint(U)
        replay occurrences of s up to and including occ into U   # 文を丸ごと次の黒へ
        (再生の途中で崩れたら下の「分割」へ)
      else:                                            # 空の黒でもこの文が入りきらない
        restore(U, last_stable); close_and_carry(O, 0) # 文をここで分ける（台帳: split）
        U = O[0]; admit(U, occ) は必ず通る（L-308）

admit(U, item):                                         # 段 0: item=出来事 / 段 k: item=子のパック
  G = new elements of item not yet placed in U
  A = { e ∈ U.dormant_inh : item の語が vocab(e) にある }  # 起こす（L-307）
  try: resettle(U); insert(U, G ∪ A); settle(U)        # L-71, L-64
  except Budget: return False
  move A from dormant_inh to active_inh; record admit/activate; return True

close_and_carry(O, k):
  U = O[k]; P = pack(U); U.status = closed; ledger close/pack
  if k+1 == len(O): O.append(new_unit(k+1, carry=∅))   # 新しい最上段（その時点の前線は空）
  if not admit(O[k+1], P):                             # 赤が崩れた → 赤を閉じて青へ（再帰）
     restore(O[k+1], before P); close_and_carry(O, k+1)
     admit(O[k+1], P) は新しい赤の最初の項目（L-308 で必ず通る）
  O[k] = new_unit(k, carry = snapshot(F(k)))           # 繰り上がりの後に写す: 今閉じた P を含む
```

- 新しい黒の引き金: 黒が崩れて閉じたとき（文の境界へ戻す。§4.1）。
- 新しい赤の引き金: 黒のパックを赤に入れて赤が崩れたとき。新しい青: 赤のパックを青に入れて青が崩れたとき。以下同じ。
- 流すもの: 段 k の閉じた単位のパック → 段 k+1 の新しい要素。段 k+1 以上の新しい要素の全て（前線）→ 次に開く段 k の単位の持ち越し（写し）。
- 進行の保証（L-308）: 新しい単位の最初の受け入れが崩れたら、起こす群 A を外して（引き継ぎは眠ったまま、台帳に `activation_deferred`）要素 1 つだけを入れる。要素 1 つの類は必ず安定（中心に置くだけ）なので無限に回らない。
- 流れの終わり: 開いた単位は開いたまま（無理に閉じない。L-310）。問いは開いた単位も読む。

## 5. 問いの手順

### 5.1 入口: 一番新しい単位が全体の圧縮を持つ

一番新しい黒 O_0 の持ち越し（前線の写し）と O_0 自身で、過去の全ての出来事が重ならずに覆われる。問いはここから入る。

1. 問いを切り、V2 で機能語を外す（`cycle.split_question` と既定の filter）。Q = 最初の層の単位（M-5(c)、T7b と同じ）。
2. **入口の集合**: 開いた単位 O_D, …, O_1, O_0（前線のパックは O_1..O_D の新しい要素なので、これらを読めば前線を全て読む）。
3. **正確な飛ばし（L-313）**: 単位 U の問いの重み rq(U) = Σ_{q∈Q} |{s ∈ sids(U) : U の範囲で s が q を含む}|。rq(U)=0 なら U を読んでも N-03 の接地が無く必ず UNKNOWN_NO_EVIDENCE なので読まない（結果は読んだ場合と同じ。試験で確かめる）。これは索引の参照で、証拠の数えではない。

### 5.2 粗から細へ降りる

```
queue = 入口の単位のうち rq>0 のもの
while queue and 予算が残る:
  次の読み = queue の中で (段 降順, rq 降順) の先頭の同値の群（同値は一緒に読むか読まない、L-314）
  for U in 群:
    res = cycle._ask_tier_once(U の局所空間, plan_override=[U の十字], units=Q, V3 既定, QueryBudget)
    ans = readout.read_out_result(...)            # 採られた状態の断面の経路
    for 経路上の要素 x がパック:                     # 段 k≥1 の単位、または段 0 の起きた引き継ぎ
       queue に unit(x) を足す（rq>0 のときだけ。引き継ぎなら印 lateral）
    段 0 の U なら、経路の語を候補にする
```

- 降りる先は**選ばれた経路上の要素の下だけ**（C-5「ショートカット」。T8 の L-243 と同じ考え）。上の段で状態が採られなかった（UNKNOWN_*）単位からは降りない。既定はこれ。比較のため、索引だけで降りる版（rq>0 の子を全て）を旗 `fallback="index"` として持ち、測る（L-316）。
- 黒の経路上に起きた引き継ぎのパックがあれば、そのパックの単位（過去の黒・赤）へ**横に降りる**（印 lateral）。これが「黒が前の全てを持って始まる」ことの問いでの使い道。
- 同じ単位は 1 回だけ読む。読む順番は予算で止まる場合だけ結果に効く（止まらなければ読んだ集合だけで結果が決まる。試験）。

### 5.3 読むもの・答えの形

- 候補は**段 0 まで降りて読んだ黒の経路の語だけ**（L-317）。各候補 = T6z/T7b の entry: 語の集合、並び（arrangements）、出所の文（その黒の範囲の sid、辺ごと）、参考の中心、段の印（RUN/WORD/CHAR）に加えて **鎖の印**（例 `U1:0 → P1:1 → U0:1`、lateral の有無）。
- 同じ段の中で、違う黒から同じ語の集合が出たら 1 つの entry にまとめ、全ての出所を残す（【T6y の後】「似ている＝語の集合が同じ」）。段（RUN/WORD/CHAR）をまたいではまとめない（L-220）。
- 経路の語が引き継ぎのパックのとき: entry の中にその要素を `{"inherited": true, "pack": "P1:0", "unit": "U0:0"}` として残す（語に展開しない。展開は降りて読んだ黒の候補として別に出る）。その辺の出所は今の黒の範囲の文（新しい証拠）だけ（条件 2）。
- 上の段の経路（どのパックを選んで降りたか）は `thought` に出す（【N-10】思考過程）。上の段のパックの語の集合（vocab）は数百語になり候補として選べないので一覧には出さない（L-317。T8 は上の段の候補を出しているので、比較では両方を数える）。
- 判定: entry 1 つ = ANSWER、複数 = CHOICE（一覧は利用者の選択用、上限なし N-20、多すぎの印 L-21）、何も読めない = UNKNOWN_NO_STATE / UNKNOWN_NO_PATH（T7 と同じ型）。利用者の選択は T7b の `memory_record` に鎖の印を足して記録する（基盤は変えない、M-4 (a)）。

| 名前 | 1 段あたり読む単位（十字）の上限 | 問いの予算 | 再構築 |
|---|---|---|---|

## 6. 3 条件の強制と試験（機械で確かめる受入）

`carry_check.py` は構築とは独立のコード（trace_check と同じ立場）で次を確かめる。全て 100% を要求し、改ざんを検出する試験を付ける。

### 6.1 条件 1: 出所を失わない

| id | 検査 |
|---|---|
| P-1 分割 | 段ごとに、全単位の範囲が全出来事を重ならずに覆う（各 (sid,pos) がちょうど 1 回。Σ|範囲| = 出来事の数） |
| P-2 パック | own_occ(P) == scope(unit(P))。段 k≥1 で scope(U) == ⊎ own_occ(新しい子パック) |
| P-3 降りる | 全てのパックと vocab の全ての語 w について、パックの下に w を新しい語として持つ黒があり、その黒の範囲に w の出来事がある。パックの下を全て降りて集めた出来事 == own_occ(P) |
| P-4 答え | 全 entry の全ての語が（黒, 席, sid）まで辿れる（L-155/L-183 と同じ検査を黒の局所空間で）。鎖の全ての要素が存在し、鎖を降りるとその黒に着く。引き継ぎの要素は unit を持つ |
| P-5 改ざん | 子の参照を 1 つ消す、sid を 1 つ消す、vocab に語を足す → 検出 |

### 6.2 条件 2: 引き継ぎを証拠として数え直さない

| id | 検査 |
|---|---|
| I-1 作り直し | 各単位について、局所空間を「範囲の出来事＋要素の定義」だけから作り直すと、保存した／増分で計算した n・p・r0・鍵・類と byte 一致 |
| I-2 毒入りの過去 | 試験用の流れで、単位 U の範囲の外の文（引き継ぎの元の文）の単位を書き換える（例: 問いの語を足す）。U の n・p・r0・E_Q・F・B・鍵・類・安定度 inv・V3 の共有点数が全て byte 一致のまま（変わるのは降りた先の候補だけ） |
| I-3 印 | 全単位で new と active_inh と dormant_inh が互いに素。引き継ぎは new に入らない。vocab に引き継ぎ由来だけの語が無い。出力の引き継ぎ要素は全て `inherited: true` と元の unit を持つ |
| I-4 答えの証拠 | entry の出所の sid は全てその黒の範囲の中。上の段の読みは thought にだけ出て、entry の証拠（数）に入らない |

### 6.3 条件 3: 順番を固定し、台帳に残し、変化を測る

| id | 検査 |

### 7.2 指標

| 群 | 指標 |
|---|---|
| 速さ | 1 問あたり読んだ十字の数（段ごと、lateral・飛ばしの数）、問いの時間（中央値・p90・最大）、構築の時間、1 出来事あたりの受け入れ時間 |

## 10. 範囲と注意

- しないこと: 既存の `placement.py`・`cycle.py`・`readout.py`・`matryoshka.py` の変更（T8 実装中）、記憶の層（T11）、ロック（I-23）。
- 予見される帰結（測って示す。直すと意味が変わるので実装役は直さずに上げる）:
  1. 起きた引き継ぎは新しい語の「過去」として多くの文に含まれ、黒の中心になりやすい（§4.5）。中心は参考なので答えの語には効きにくいが、経路を短くする可能性がある。
  2. 文が黒をまたぐと、またいだ語どうしの共有は黒の中で見えない（OP-2）。上の段では見えるが、候補は黒からだけ出る（L-317）ので、その共有に頼る答えは出にくい。
  3. 構造が流れの順番に依存する（条件 3 で測る）。平らな構造（F）にはこの依存が無い。
  4. 黒の大きさは予算の段で決まる（OP-3 (a)）。予算を上げると黒が大きくなり段が浅くなる。
  5. 構築は遅い（§4.4）。S30000 は部分になる可能性があり、その場合は印を付けて報告する。
