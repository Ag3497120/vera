# 読解器の出力の書式と表記の決め方（B1 意味読解バンクの採点に合わせるための規約）

出典: B1 v2 設計書の付録（共通規約）と各単位の表記規約。**問題文は含まない**。例は `X が Y を V した`・`A は B より C` のような
記号の型だけで書く。この文書は、読解器（の採点用アダプタ）が返す出力の **書式** と、値の **書き方の決まり** だけを
実装チームに渡すためのもので、バンク本体（問題・正解・誤読の型の表）は含まない。
採点は `tools/bank_score/v2/b1.py`（設計者の `score.py` の移植）が行う。この文書の規約に従って正しく読んだ出力が、
書式の違いだけで「不完全」にならないようにするのが目的。

## 1. 出力の形

読解器は 1 問（1〜2 文の入力）につき、次の形を返す。

```json
{"readable": true,
 "clauses": [ {節}, ... ],
 "relations": [ {"type": <種類>, "from": <節番号>, "to": <節番号>}, ... ]}
```

- `readable: false`（読めない）は **型付きの結果の状態**（棄権）で返す。文字列の「読めません」では判定されない。
  `readable: false` のときは `clauses: []`、`relations: []`。
- 読解器には **入力の文字列だけ** を渡す。問題の分類名・現象の説明・誤読の型・分野・理由を渡してはならない
  （渡すと、読めない入力がラベルだけで当たってしまう）。
- 役割の値は **1 つの文字列**。候補を並べた配列で返した役割は不一致になる（全候補を列挙して点を取る戦略を無効にするため）。
  配列で返しても、後述の誤読（must_not）の照合には使われるので、列挙は誤読として数えられる。
- `clauses` の並びは、述語が入力に現れる順（日本語も英語も述語の語の位置で並べる）。
  採点は述語と役割で突き合わせるので並びの違いでは減点しないが、`relations` の節番号は **この並びの番号** で書く。

### 1.1 節（clause）のキー

| キー | 必須 | 値 |
|---|---|---|
| `predicate` | 必須 | 述語の辞書形（§3） |
| `roles` | 必須 | `{役割名: 値}`。役割が無ければ `{}` |
| `polarity` | 必須 | `"+"` か `"-"`（§5） |
| `tense` | 必須 | `"past"` / `"nonpast"` / `null`（§5） |
| `modality` | 必須 | `null` か §5 の一覧の 1 つ |
| `voice` | 必須 | `"active"` / `"passive"` / `"causative"` / `"causative_passive"` |
| `quantifiers` | 量化があるときだけ | `{役割名または "event": 値}`（§6）。量化が無い節には書かない（値が null の飾りの欄を全節に付けない） |
| `scope` | 演算子が 2 つ以上のときだけ | 広い順の配列。要素は `"neg"` か、量化のかかる役割名（§6） |
| `comparison` | 比較の節だけ | `"comparative"` / `"equative"` / `"superlative"` |

### 1.2 節の鍵の表（relations）

`relations` の 1 要素は `{"type": <種類>, "from": <節番号>, "to": <節番号>}`。種類は閉じた一覧で、向きは次のとおり。

| type | from | to | 主な形（接続の型） |
|---|---|---|---|
| `cause` | 原因の節 | 結果の節 | 〜ので・〜ため・〜から・because・so |
| `contrast` | 前の節 | 後の節 | 〜が・〜けれど・but |
| `concession` | 譲歩の節 | 主節 | 〜ても・〜のに・although・even if |
| `condition` | 条件の節 | 帰結の節 | 〜ば・〜たら・〜なら・〜と・if・unless |
| `purpose` | 目的の節 | 主節 | 〜ために（目的）・〜ように・in order to・so that |
| `sequence` | 先に起きた節 | 後に起きた節 | テ形の連続・〜てから・〜後で・〜前に・連用中止・and then・before・after・分詞構文（完了） |
| `simultaneous` | ながら／while の節 | 主節 | 〜ながら・while |
| `manner` | 手段・様態のテ形の節 | 主節 | 手段・様態を表すテ形 |
| `quote` | 伝達の節 | 内容の節 | 〜と言う・〜と思う・say・tell・ask |
| `relative` | 関係節 | 被修飾名詞を含む節 | 連体修飾節・who / which / that・縮約関係節 |
| `content` | 内容節 | 主節 | 〜という知らせ・the news that … の型 |

- 正解が 2 つの種類のどちらにも読めて割れないとき（テ形が原因にも順序にも読める場合など、設計が認めたとき）は、正解側が
  `type` を配列で持つ。**出力側は 1 つの種類を返す**（正解の配列のどれか 1 つと一致すればよい。出力側の配列は不一致）。
- 3 節以上の順序・連鎖は、隣り合う組ごとに書く（0→1、1→2）。0→2 は書かない。
- 接続語も構文も無い 2 文の間には `relations` を書かない。接続語（それで・だから・then など）が書かれているときだけ書く。

## 2. 役割名（閉じた一覧）

この一覧の名前だけを使う。読解器側の別名（`means`・`location`・`direction`・`limit`・`subject` など）は、採点アダプタで次のように写してから返す。

| 役割 | 何を入れるか | 読解器側の別名の例 |
|---|---|---|
| `agent` | 他動詞の主語。人・動物・組織が主語の自動詞の主語。受身の動作主。授受動詞の与え手。〜てもらう で実際に動作をした人 | agent |
| `patient` | 動作の対象。直接受身の主語 | patient |
| `recipient` | 物や情報を受け取る人・組織 | recipient |
| `goal` | 移動・設置の到達点（場所・物） | goal・direction・limit |
| `result` | 変化・変換の結果（〜に変える・〜になる・〜に分ける・〜に訳す・turn into） | （対応する名が無い。読解器は別の役割（recipient など）に誤る） |
| `source` | 起点・出どころ・材料（から・より・from・out of）・入手元の人 | source |
| `place` | 出来事・存在の場所 | place・location・setting |
| `time` | 時を表す語句（助詞の有無を問わない。by / until など期限の句も time） | time |
| `instrument` | 道具・手段・言語・材料（で・with・by） | instrument・means |
| `companion` | 一緒に行う人 | companion・accompaniment |
| `cause` | **名詞句**で表された原因（節の原因は relations で表す） | （対応する名が無い） |
| `quotation` | 発言・思考・記載の内容の文字列 | quotation |
| `entity` | 人・動物・組織以外が主語の自動詞の主語、形容詞・名詞述語・存在文の主語、比較される側 | subject（比較）など |
| `value` | 名詞述語の述部（「A は B だ」の B）、比較の差分量 | value |
| `attribute` | 「A は B が 形容詞」の B（側面） | （対応する名が無い） |
| `standard` | 比較の基準、最上級の範囲 | （対応する名が無い） |
| `causer` | 使役の「させた側」 | （対応する名が無い） |
| `causee` | 使役で実際に元の動作をした人 | （対応する名が無い） |
| `beneficiary` | 〜てあげる／くれる／もらう の恩恵を受ける人、for＋人 | （対応する名が無い） |
| `experiencer` | 間接受身（迷惑の受身）で影響を受ける人 | （対応する名が無い） |

- 自動詞の主語の決め方（機械的な規則）: 主語が人・動物・組織なら `agent`、それ以外（物・現象・機械・時間・抽象物）なら `entity`。
  判断が割れる主語（ロボット・AI など）は使わない。
- 決められない格を `ambiguous` という役割名で返す読解器は、採点アダプタが「その項を落とす」か「その節を棄権として扱う」かを
  先に決めておく。`ambiguous` をそのまま役割として出力すると不一致になるだけ。
- 組織としての地名（支所・支社・工房・自治体名）が他動詞の主語なら `agent`。
- 副詞（すぐ・ゆっくり・quickly など）は役割にしない。

## 3. 値の書き方

- **述語**: 辞書形。日本語は「〜ます／〜た／〜ている／〜てしまう／〜ておく」を外した形。サ変は「名詞＋する」。複合動詞は 1 語。
  「N になる」は `なる` に `result: N`。形容詞は終止形、形容動詞は「〜だ」、名詞述語は `だ`（英語は `be`）。
  受身・使役の助動詞は外して `voice` で表す（元の動詞を辞書形にする）。可能形は元の動詞に modality `ability`。
  尊敬語・謙譲語の動詞はその語の辞書形。英語は動詞の原形、句動詞は空白でつなぐ。be＋形容詞は形容詞。
  **言い換えた語を述語にしない**（元の語と同じ意味の別の語に替えない）。
  表記の揺れを許す問題は、正解側が配列で持つ（読解器は 1 つの表記を返す）。多義語は、文脈で決まる語の辞書形を正規形にする。
- **名詞句**: 格助詞・係助詞（は・も）を外す。連体修飾節は外して主要部から書き、関係節は別の節にする。
  「の」の修飾と形容詞の修飾は残す。量化の語（すべての・3 人の・every・three など）は値から外して `quantifiers` に入れる。
  指示詞の連体詞と英語の冠詞・指示詞は外す。敬称は書いてあるとおり残す。
- **代名詞・省略**: 先行詞が **入力の中にある** 代名詞と省略された項は、先行詞の名詞句で埋める（値は先行詞の書き方そのまま）。
  引用の中の一人称は話し手、二人称は入力に聞き手があれば聞き手で埋める。**先行詞が入力に無い** 省略はその役割を書かない
  （推測で「私」を補わない）。先行詞が入力に無い代名詞は、書いてあるとおりに書く。
- **時間**: 書いてある語句そのまま。「A から B まで」のような幅は 1 つの `time` にまとめる。英語は前置詞と冠詞を外す
  （期限を表す by / until / before のように意味が変わる前置詞は、正解側が両方の形を許す）。
- **引用**: `quotation` の値は、引用符・「と」・that・whether を外した中身の文字列。
- 照合の正規化は §8 を見る。値の表記の違い（漢字とかな、送り仮名）を採点は吸収しない。

## 4. 格・時と場所・態と授受・引用など話題ごとの表記の決め方

### 4.1 格（に・から・で・を などの役割）
- に＋人・組織で、物・情報がその人に移る → `recipient`。に＋場所・物で、物がそこに移る → `goal`。
  に＋変化後の状態・形式・言語・数 → `result`。
- 「〜に変換する」の型の述語はサ変。「〜になる」は `なる` に `result`。
- から＋人（借りる・もらう以外の動詞）→ `source`。
- 英語の二重目的語「X が Y に Z を渡す」の型は `agent: X`・`recipient: Y`・`patient: Z`。
  「translate A into B」の型は `patient: A`・`result: B`。

### 4.2 時・場所
- 時の句は `time` に、書いてある語句そのまま。読点は値に含めない。
- 「〜では」「〜で、」の場所は `place`。主題の「は」は外す。
- 存在文「〜に〜がある／いる」は述語 `ある` / `いる`、`entity` と `place`。英語の there 構文は述語 `be`、`entity` と `place`。
- 受身の出来事は述語を能動の辞書形にして `voice: "passive"`。動作主が書かれていなければ `agent` を書かない。

### 4.3 否定・量化・スコープ
- 極性・量化・スコープは §5・§6 の規則に厳密に従う。割れる形（読みが 2 通りになる語順など）は、バンク側が問題に入れない。
- 二重否定で modality が付く形（〜ないわけにはいかない の型）は modality を必ず書く。
- 関係節を含む文は 2 節にし、`relative` を付ける（被修飾名詞は関係節の欠けた役割に入れる）。
- 数と助数詞: `exactly:3` のように数だけ。助数詞（本・件・人）は値に入れない。遊離した数量も、それがかかる名詞の役割をキーにする。
  「各」「それぞれ」「each」は `universal`。

### 4.4 比較
- **形容詞・形容動詞が述語の比較**: `predicate` は形容詞の終止形（英語は原級。比較級の語形にしない）。比較される側は人でも物でも `entity`。
  基準は `standard`（「より」「ほど」「than」「as」を外す）。差分は `value`。
- **動詞の比較**（多く・早く＋動詞、「more X than Y」の型）: 述語は動詞、主語は §2 の規則（agent / entity）、基準は `standard`。量の語は役割にしない。
- `comparison`: 「より」「than」→ `comparative`、「ほど」「同じくらい」「as … as」→ `equative`、「一番」「最も」「-est」→ `superlative`。
- 最上級の範囲を表す句（「N の中で」「of …」の型）→ `standard`（「の中で」「of」を外す）。範囲が書かれていない最上級は `standard` を書かない。
- 評価の形容詞の表記の揺れ（漢字とかな）は、正解側が配列で両方を許す。

### 4.5 関係節
- 関係節は **別の節** にする。被修飾名詞は、関係節の節では欠けた役割の値に、主節では主節での役割の値に、両方入れる
  （値は主要部から書く。関係節の部分は値に含めない）。
- `{"type": "relative", "from": <関係節>, "to": <被修飾名詞を含む節>}`。内容節は `{"type": "content", "from": <内容節>, "to": <主節>}`。
- 節の並びは述語の出現順。日本語は普通、関係節の述語が先。英語は主節の述語より後に関係節の述語が来ることがある。
- 関係節では tense をその節の形で決める（た → past、る → nonpast）。英語の縮約関係節は `null`。
- 内容節の名詞（知らせ・噂・決定 の型）は主節の役割に入る。内容節に欠けた役割は無い。

### 4.6 態と授受
- **受身**: 述語は能動の辞書形、`voice: "passive"`。直接受身の主語は `patient`、に／によって／から の句は `agent`。
  間接受身の主語は `experiencer`、に 句は `agent`、を 句は `patient`（あれば）。
- **使役**: 述語は元の動詞、`voice: "causative"`。させた側は `causer`、実際に動作をした側は `causee`、元の動詞の目的語は `patient`。`agent` は書かない。
- **使役受身**: 述語は元の動詞、`voice: "causative_passive"`。主語は `causee`、に 句は `causer`、を 句は `patient`。
- **授受動詞（本動詞）**: 述語はその動詞（`あげる`・`くれる`・`もらう`）。与え手が `agent`、受け手が `recipient`、物が `patient`。
  `もらう` の主語は `recipient`、に／から 句が `agent`。
- **〜てあげる／くれる／もらう**: 述語は本動詞（「V てもらう」なら `V`）、`voice: "active"`。実際に動作をした人が `agent`、
  恩恵を受ける人が `beneficiary`。書かれていない恩恵の受け手は書かない。
- **英語の使役**: 「X made Y V Z」の型 → 述語 V、`causer: X`・`causee: Y`・`patient: Z`。
  「X had Z V-ed by Y」の型 → 述語 V、`causer: X`・`causee: Y`・`patient: Z`。
- 動作主が書かれていない受身・使役では、その役割を書かない。

### 4.7 引用
- 伝達の節: 述語は伝達の動詞（`言う`・`伝える`・`尋ねる`・`話す`・`say`・`tell`・`ask`）、`agent` は話し手、`recipient` は聞き手（書かれていれば）、
  `quotation` は内容の文字列。
- 内容の節: 内容を述語項構造として **別の節** にする。`{"type": "quote", "from": <伝達の節>, "to": <内容の節>}`。
  内容の節の人称は §3 のとおり解決する。内容の節の tense は内容の中の形で決める。
- 内容の中で主語が省略されていて、文脈から話し手自身と決まる場合は、内容の節の `agent` は話し手。決まらない場合は書かない。
- 伝聞（話し手が書かれていない）: 内容の節 1 つだけ、modality `hearsay`。伝達の節は作らない。
- 疑問の内容（whether・かどうか の型）の節は modality `question`。`quotation` の値からは whether を外す。

### 4.8 省略と照応
- `clauses` は 2 文の述語を出現順に並べる（1 文目の節が先）。
- 省略された項・代名詞は先行詞の名詞句で埋める（§3）。先行詞が入力に無ければ書かない。
- 2 文の間の関係は、接続語が書かれている場合だけ `relations` に書く。

### 4.9 接続
- 各節を別の節として書き、`relations` で結ぶ（§1.2 の向き）。節の並びは述語の出現順。英語の後置 because（「Y because X」の型）では
  Y が 0、X が 1 で、`{"type": "cause", "from": 1, "to": 0}`。
- tense: ので・から・が・けれど・のに・because・although・but・so の節は定形なので past / nonpast を書く。
  ても・ば・たら・なら・ために・ように・if・unless・even if の節は `null`（§5）。
- 主節の主語が従属節と同じで省略されていれば、その主語で埋める（入力の中にあるので）。
- 「〜ために」が原因か目的かは、ため の前が動作の意図か（目的）、起きた出来事か（原因）で決まるものだけが問題になる。

### 4.10 順序
- 各述語を別の節にする。共有された主語・目的語は各節に同じ値で入れる。
- `sequence`: from＝先に起きた節、to＝後に起きた節。`simultaneous`: from＝ながら／while の節、to＝主節。
  `manner`: from＝手段・様態のテ形の節、to＝主節。3 節の連鎖は隣り合う組ごと。
- tense: テ形・連用中止・ながら・前に・分詞の節は `null`。主節と、〜た後で・after・before の定形の節は past / nonpast。

### 4.11 多義と長い複文
- **多義**: 述語は文脈で決まる語の辞書形（漢字）を正規形にし、入力の表記（かな）を配列で許す（正解側）。役割名は §2 の定義どおり
  （原因の「で」→ `cause`、材料の「から」→ `source`、期限の by → `time`、for＋人 → `beneficiary`）。
- **長い複文**: 節は 3〜5。各節に §3 の規則どおりの値、`relations` は節の組ごとに書く
  （関係節 → `relative`、因果 → `cause`、譲歩 → `concession`、テ形 → `sequence`、引用 → `quote`、条件 → `condition`）。

### 4.12 読めない入力
- §7 を見る。対照文（読める入力）は §2〜§6 のとおり読む。読めない判断の手がかりになった部分（感動詞など）を構造化しない。

## 5. 極性・時制・モダリティ

- **polarity**: その節の述語が、否定をすべて計算した後で肯定か否定か。
  - 単純否定（ない・ません・ず・not・never）→ `"-"`。
  - 二重否定（〜ないわけではない・〜なくはない・〜ないことはない の型、not un…、didn't fail to）→ `"+"`。
  - 「〜なければならない」「〜ないわけにはいかない」→ `"+"` と modality `obligation`。
  - 「A しか〜ない」「only A」→ `"+"` と `quantifiers: {A の役割: "only"}`。
  - 「誰も／どの〜も〜ない」「no X」「none of」→ `"-"` と `quantifiers: {X の役割: "none"}`。
  - 部分否定（すべて〜わけではない・全員が〜とは限らない・not every・not all）→ `"-"` と `quantifiers: {役割: "universal"}` と `scope: ["neg", 役割]`。
  - 「〜てはいけない」「must not」→ `"+"` と modality `prohibition`（否定はモダリティの中にある）。
  - 「unless X」の X 節 → `"-"`（「if not X」として書く）。
- **tense**: 主節・関係節・「ので／から／が／けれど／のに／because／although」などの定形の従属節は `"past"` か `"nonpast"`
  （英語の will も `nonpast`、完了形も過去なら `past`）。テ形・連用中止・ば／たら／なら／ても／ながら／ために／ように・英語の不定詞・
  分詞構文・if / unless 節の節は `null`（採点しない）。引用の中の節はその中の形で決める。**正解が `null` の節は採点しない**
  （出力側が値を返しても減点しない）。
- **modality**（閉じた一覧）: `null`、`ability`（可能形・できる・can）、`obligation`（なければならない・べき・must・have to）、
  `permission`（てもいい・may〈許可〉）、`prohibition`（てはいけない・must not）、`volition`（〜よう・つもり・intend to）、
  `desire`（たい・want to）、`request`（てください・命令形・please）、`possibility`（かもしれない・might・may〈推量〉・could〈推量〉）、
  `conjecture`（だろう・でしょう・probably・likely）、`hearsay`（そうだ〈伝聞〉・らしい・という・reportedly・is said to）、
  `question`（尋ねた内容の節）。「want to V」「intend to V」は V を述語にする。

## 6. 量化とスコープ

- `quantifiers` の値（閉じた一覧）: `universal`（すべて・全員・各・every・each・all）、`existential`（ある・いくつかの・何人か・some・a certain）、
  `most`（ほとんど・大半・most）、`partial`（一部の・some of）、`none`（誰も〜ない・no・none of）、`only`（だけ・のみ・しか〜ない・only）、
  `exactly:N`（ちょうど N・N〈数だけ〉・exactly N・three）、`at_least:N`（N 以上・少なくとも N・at least N）、`at_most:N`（N 以下・at most N）、
  `more_than:N`（N を超える・more than N）、`less_than:N`（N 未満・fewer than N）、`approx:N`（約・およそ・about）。N は算用数字。
- キーは量化のかかる役割名。回数（N 回押した の型）は `"event"`。
- `scope` は演算子（否定と量化）が **2 つ以上** ある節だけに書く。広い順に並べる。部分否定は `["neg", 役割]`、
  「どの A も少なくとも N 個を〜した」の型は `[A の役割, 目的語の役割]`。
- 量化の語を含むが量化していない複合語（固有の行事名・制度名・組織名の型）は量化として書かない。
- 読みが 2 通りに割れる語順は問題に入れられない。

## 7. readable: false にする入力・しない入力

`readable: false`（`clauses: []`、`relations: []`、棄権の状態）にするのは次のどれかだけ。
1. 挨拶・お礼・謝罪・相槌などの定型表現だけの入力
2. 感動詞だけの入力
3. 述語の無い断片（名詞句だけ・従属節だけで主節が無い・助詞や読点で終わる）
4. 実在の語を、文法的に結びつかない順に並べた語列
5. **主節の述語が造語**（辞書に無い動詞・形容詞。項や名詞は普通でも）
6. 格の重複・語順の崩れで、述語と項の対応が一意に決まらない壊れた入力

次は `readable: true`（読める）。
- 架空の固有名詞（人名・地名・製品名）を含むが、述語は実在の語である文。
- 主語や目的語が省略されていても、述語がある完結した文。
- 感動詞や呼びかけが先頭に付いた完結した文（感動詞は役割にしない）。
- 依頼・命令の文（modality `request`）。

造語の扱い: **主節（または唯一の節）の述語が造語なら、従属節や関係節が普通に読めても入力全体を `readable: false`** にする
（主な命題が読めない入力を、読めた部分だけを構造にして返すのは誤読と数える）。定型表現か命題のある文かが割れる表現は問題に入らない。

## 8. 照合の規則と 1 問の判定

### 8.1 照合（採点が行うこと）
- 文字列は NFKC 正規化・大小文字無視・前後の空白と句読点の無視。**英語の値**は、先頭の前置詞を 1 つ（`out of`・`during`・`before`・`after`・
  `behind`・`onto`・`into`・`on`・`in`・`at`・`from`・`to`・`than`・`by`・`for`・`of`・`as` のうち、この順で最初に当てはまるもの）外し、
  続けて冠詞（`the`・`a`・`an`）を外して照合する（日本語の値には前置詞の規則を当てない）。
  正解が配列のときは、どれか 1 つと一致すれば一致。出力側が配列の役割は不一致。
- 節の対応づけ: 正解の節と出力の節を、述語の一致（2 点）＋役割の一致数（各 1 点）を重みにした最大重みの対応で 1 対 1 に結ぶ
  （重みが同じなら位置のずれが小さい対応）。それでも同点の対応が複数あり、対応によって判定が割れるときは **判定不能**（勝者を作らない）。
  出力の節が 9 以上のときも判定不能。`relations` と誤読の判定の節番号は、この対応で出力側の番号に読み替える。
- 次元ごとに照合する: 述語、各役割（役割名と値の組。**余分な役割は不一致**）、極性、時制（正解が `null` の節は採点しない）、モダリティ、
  態、量化（キーと値）、スコープ（順序つき）、比較の種類、節間関係（種類・from・to。正解の type が配列ならどれか 1 つ）。

### 8.2 1 問の判定（4 つのどれか 1 つ）
1. **誤読**: 誤読の判定（バンク側が持つ「こう読んではいけない」の条件）のどれかに当たる、または、正解が `readable: false` なのに
   `readable: true` で節を 1 つ以上返した。**誤読は正答より優先**（他が合っていても誤読）。
2. **棄権**: 正解が `readable: true` で、出力が `readable: false`。誤読とは別に数える。
3. **正答**: 正解が `readable: false` で出力も `readable: false`。または、正解が `readable: true` で、出力の節が正解の節と過不足なく対応し、
   各節の述語・役割（過不足なし）・極性・時制（null を除く）・モダリティ・態・量化・スコープ・比較が一致し、節間関係の集合が一致する。
4. **不完全**: 上のどれでもない（読めたと返したが、誤読ではなく、どこかが違う）。

誤読の判定の条件（誤読の型）は、バンクの正解と一緒に非公開なので、この文書には書かない。種類だけ言うと、役割の値・述語や極性などの欄の値・
量化・スコープ・節間関係・`readable` の真偽のどれかについて「この読みは誤り」と指定される。
採点は **誤読数を第一の指標、正答率を第二** にして報告する。常に棄権すれば誤読は 0 になるので、棄権率を並べて出し、誤読数だけで合否を決めない。

9 分類（`docs/BANK_SCORE.md` §4）への写像: 誤読 → `misread`、棄権 → `over_abstain`、`readable: true` の正解に正答 → `correct`、
`readable: false` の正解に正答 → `correct_abstain`、不完全 → `wrong`（正解が `readable: false` のときは `false_compliance`）。

## 9. 規約に無い未決の点（バンク側の隔離・修正待ち）

次の話題は、規約が決めていないので、読解器がどう書いても「不完全」になりうる。バンク側は該当する問題を隔離している。
規約が決まったら、この文書に追記する。
1. 補助動詞（〜てみる・〜てある・〜ていく・〜てくる の型）を述語にどう書くか（外して元の動詞にするのが推奨。決定待ち）。
2. 文頭の時・場所の句が、どの節に付くか（読点で区切った文頭の句を、その直後の主語を持つ節にだけ付ける、が提案）。
3. 最上級の範囲を表す句の中の「all」「全」を量化として書くか（書かない、が提案）。
4. 省略された項の補い方（先行詞が一意に決まる必須の項だけを埋める、目的語なしでも使う動詞の目的語は埋めない、が提案）。

## 10. 読解器の型の不足（採点アダプタ側の対応が要る）

開発ツリーの読解器の出力と、この書式の差。
- 役割: `result`・`cause`・`standard`・`beneficiary`・`experiencer`・`causer`／`causee`・`attribute` が無いか、名前が違う
  （`means` → `instrument`、`location` → `place`、`direction`・`limit` → `goal`、比較の `subject` → `entity`）。
  読解器は助詞「に」「を」の項を `recipient` や `ambiguous` にしてしまうことがある。
- 関係: 譲歩と逆接の区別、`purpose`・`manner`・`content`・`simultaneous` の種類が足りない。
- 量化: `most` と `partial` の区別、`at_least`／`at_most` と `approx` の区別、回数の `event` が足りない。
  極性と `scope` の組（部分否定）も足りない。
- **棄権は型付きの状態（`readable: false`）で返す**。文字列で判定しない。
- 英語の経路は、意味読解の経路で全件未読になりうる。棄権は誤読ではないので合否は壊れないが、英語の正答率は別に出す。
