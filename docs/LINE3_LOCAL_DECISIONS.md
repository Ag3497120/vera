## Placement T4b: tied arrangements grown as one state (verantyx/line3/placement.py)

Owner's decisions after the T4 measurement (binding): tied arrangements are kept together as ONE state and grown; arm assignment is not distinguished; no replacement with units outside the cross; growth order by shares with the original seed.

| id | decision | location |
|---|---|---|
| L-70 | A state is a CLASS: a set of arrangements of one key, closed under single seat swaps that keep the key, and with no member from which a single move improves the key ("stable" = this fixed point of the class). No member is picked by order; the representative `Placement.cross` is the first member in canonical sorted order (a label, not a winner). Arm assignment is quotiented out (L-61). | placement.py |
| L-71 | Settling: level by level every state moves by ALL its best improving single moves (all tied results kept); terminals of the best key are taken, their closure under equal-key swaps is the class; if any member of the closure has an improving move, those moves' results (from every member) are climbed again until none has. Branches ending at the same key are the same class (union). | placement.py `_settle` |
| L-72 | Growth: the next share-group (shares with the original seed, equal shares together) is inserted into EVERY member (L-64 greedy insertion, all tied placements kept), all results are settled (L-71), the best-key class is kept. A step cannot "break" any more; it can only hit the budget. The lone seed's class is built like any other (seed at the centre or at an arm end: 2 members at L=1). | placement.py `build_cross` |
| L-73 | Budget (explicit, never a silent cut; replaces L-66): `Budget(max_class, max_states)`; max_class = most arrangements in one class, max_states = most distinct states handled in one growth step (insertion + climbing + closure). Exceeding either = BUDGET: growth stops, the previous class is restored (N-05), `Placement.stop == "budget"`, `Step.reason` names the budget, and the budget used is stored in every Placement (to_json_obj "budget"). Defaults 1000 / 20000. | placement.py |
| L-74 | Verification: `verify_class` (independent of the search; geometry's swap/rotate/edges) checks one key, every member a fixed point against all single moves, and closure under equal-key moves. `verify_fixed_point` is applied to every member in the tests. | placement.py |
| L-75 | `observe_class` takes the energy log on every member of the class (members in canonical order); `observe` / `energy_log` use the representative. Which member (or all) the later stages read is not decided here (see open points). | placement.py |

What the numbers mean: stability is now always reached (no step "breaks"); capacity is limited only by the explicit budget. A first group of many units with the same share (typical for RUN/WORD: 15-24 units with n(seed,v)=1) has an astronomically large tied class (units without mutual edges may float to any seat; the class is closed under those moves), so it cannot be enumerated and the step ends as BUDGET with the lone-seed class restored (class size 2 = seed at the centre or at an arm end; capacity 1). Symmetric toys grow (e.g. "A B C": capacity 3; "A B"/"B A": class of 2, centres A and B). Class sizes of kept states are reported per Step.class_size and Placement.class_size.

## Placement T4d: interchangeable units held as one (verantyx/line3/placement.py)

Owner's decision after the T4c measurement (binding): 「入れ替えても同じ語どうしは並べ方を数えない」. Stability values and the set of states do not change; only the counting.

| id | decision | location |
|---|---|---|
| L-90 | Interchangeable (twins): u, v of the candidate pool P (the seed and every unit with n(seed,.) > 0) are interchangeable iff the transposition (u v) is an automorphism of the edge weights w = (n, p) (outer -> inner) on P: w(u,z) == w(v,z) and w(z,u) == w(z,v) for all z in P \\ {u,v}, and w(u,v) == w(v,u). Then swapping u and v cannot change the I-04 key of any arrangement of units of P (hence of the cross). It is an equivalence relation ((u x) = (u v)(v x)(u v)). `find_twins` (bucketed by the multiset of a unit's weights, then pairwise `are_interchangeable`) gives {unit: smallest unit of its class}. | placement.py |
| L-91 | The search runs on LABELS (one label per twin class; two slots with the same label hold two different twins and use w(u,v)). The held class is a class of label arrangements (`Placement.members`, `class_size`); the EXPANDED class (= the T4c class) is every assignment of the placed units to the label slots, up to arm assignment (`expanded_members()`, `crosses()`, `twin_sets`), counted without enumeration by `expanded_count` / `expanded_size` (also per Step). `Placement.cross` is the first expansion of the first member; member labels are the smallest placed unit of the class; `centres` lists every unit that may sit at the centre. Budget numbers (max_class, max_states, max_moves) count quotient items; levels unchanged. `quotient=False` is the T4c search exactly. | placement.py |

### T4d measurement (same seeds/levels as T4c; experiments/line3/budget_curve/results/*_q.jsonl, curve_q.md, run_level_q.py, summarize_q.py)

Result: on S300, in all 3 tiers and all 5 levels (RUN/WORD/CHAR 240 seeds, max 48/48/20), NO seed has any interchangeable pair (twins = 0). Capacity, stop reason and class size are identical to T4c on every seed (expanded size == T4c class size on all 3 x 5 sets); the quotient saves nothing; wall time is higher by the twin detection (O(|P|^2) weight lookups per seed; runs were executed 11-12 in parallel on 10 cores, so absolute times are not comparable with T4c, ratio about 1.2x-4x). A check at the budget-breaking steps (low level, 34 / 39 / 40 budget-stopped seeds of 40 per tier RUN / WORD / CHAR) with the weaker, step-local definition (invariance only on the units already in the cross plus the breaking group) also found no twin. Reason: units that share a sentence with the seed differ in word-order weights p (and in n) towards the other pool units, so no transposition is an automorphism; the huge T4c classes come from DIFFERENT arrangements whose key sums happen to coincide, not from swapping equivalent units. The quotient is proved only on toys that have genuine twins (e.g. "A B"/"B A": held 1, expanded 2; "X A".."X H": held 1 class, 840 expanded arrangements, T4c cannot count it under the same budget) and on S300 seeds (expansion == T4c class where T4c fits).

### T5 measurements

## OPEN POINTS (owner questions; behaviour not changed)

- RUN tier: question words are not separate units (`units_run('半田岩はどこにありますか')` gives `['半田岩', 'はどこにありますか']`), unlike the WORD and CHAR tiers. The T1 docstring now states this; whether the RUN tier should split them is the owner's decision.
- T4b (class growth): (a) With the owner's rule, "stable" is always reachable, so capacity is decided only by the budget; for groups of many equal-share units the full tied class cannot be enumerated (RUN/WORD median capacity is still 1, now because of BUDGET, not because of a tie). Whether to (i) raise the budget, (ii) represent the class implicitly (e.g. also treat arrangements that differ only by permuting interchangeable units - same share and same pair weights to every cross member - as one arrangement), or (iii) restrict the class to arrangements where every placed unit has a non-zero edge, is a meaning-level choice left to the owner. (b) RESOLVED by the owner (T4c, L-77): empty centre is not an arrangement. (c) Owner: read all members, adopt the one most stable after the query (query stage; the energy log is still taken on the representative / observe_class until then). (d) The class members have different centres, so "the centre" is a set (I-02, centres). 
- T4 placement (see report): (1) leg-to-leg arrangement: the I-04 key is identical for all 30 rotation classes of leg permutations, so the stability definition does not fix which arm holds which leg; sections (I-09 windows) do see adjacency. Left undetermined (L-61). (2) Budget values (L-66) change the capacity of some seeds (CHAR, S300: 2 of 233 sampled). (3) Design 3.4 "pool の外の単位とも" replacement not implemented (L-60). (4) Order anchor of M-1(b) is the fixed seed although the search may move the centre (L-63/L-68). (5) A lone seed is declared stable by definition (L-63); with moves into empty seats it has equal-key alternatives.

- T4c: (a) Per-tier reachability: even at max, 62-95% of RUN/WORD/CHAR seeds (30/48, 45/48, 19/20) stop by BUDGET with a capacity far below the ceiling (candidates+1); whether a different representation of the tied group (e.g. interchangeable units as one arrangement, option (ii) above) is wanted, or the ceiling-limited small capacity is acceptable, is the owner's choice. (b) CHAR mid capacity fell from T4b (mean 25.17 to 21.65) after the empty-centre exclusion at identical budget; the cause is not analysed. (c) The "stable after the query" comparison for owner point (3) needs a definition of query stability over a class (which energy / ratio; ties among members) - left to the query stage. (d) Default `Budget()` is "mid"; which level is the product default is undecided.

- T4d: (a) The strict interchangeability (L-90) never occurs in S300, so the budget problem of T4c is unchanged (62-95% BUDGET at max). The tied classes are made of arrangements that are different and merely have equal key sums. Whether to (i) accept this, (ii) define a weaker equivalence that is still exact for the key, e.g. arrangements equal after ignoring edges that carry (0,0) weight, or arrangements with the same multiset of edge weights (a coarser class: NOT the same set of states, owner decision), or (iii) restrict the class to arrangements where every placed unit has a non-zero edge, is a meaning-level choice. (b) Twin classes are computed over the whole candidate pool (strict, as specified); a step-local definition (twins only relative to units already placed) would be more permissive but needs splitting a held label when a later group distinguishes its members; it also found no twin on the measured budget-stopped steps. (c) Which of the twins is shown as the label of a class (smallest placed unit) is a label only. (d) Query stage: reading "all members" means reading the expansion; with twins held as one this can be done per quotient member and mapped to units; not implemented.

- T5 (query cycle) open points, nothing below is decided by the code beyond the flagged default:
  (1) M-2(a): amount counted in crosses; tied equal-E_Q groups are never split (reading stops before a group that does not fit); the three groups (query-unit crosses / crosses holding a unit that shares a sentence with a query unit / the rest) are the design's recommended reading. The owner's option "compress lower-structure results vs keep granularity" is not specified by the T5 row (it needs layers): NOT implemented, belongs to T8.
  (2) M-5(c): only the first query layer (6 units) enters the energies and sections; units from the 7th on (for WORD/CHAR most question words such as "ます か") are only recorded as inner layers. Flag `scope="whole"` reads all units with the same sections; which is meant is the owner's choice.
  (3) Leg-to-arm assignment: placement does not distinguish which arm holds which leg (T4b), but at query time the query units sit on fixed world sections, so the assignment matters. Each class member is read with its legs in canonical order; other assignments are reachable only through the 24 rotations and the seat swaps. Reading all assignments (up to 720 per member) is not done.
  (4) I-12 key: the exact meaning of "指す先の種類数 − 1" when a ratio points nowhere (L-101: its own vote) and of "エネルギーが中心へ" (F of the unit at the centre, not of the agreed unit) is a reading.
  (5) Stability inv (L-103) counts only moves that change the state; its "result" is the grounded agreed unit. Under this definition a member that never answers can be perfectly stable; the member choice (L-107) therefore has two rules and the run reports both (identical on S300 for every verdict count).
  (6) Ties: tied best moves branch; end states that differ in result (even answer vs no answer) are AMBIGUOUS, not ranked by key. About 5 percent of RUN class members end AMBIGUOUS at 64/8 (up to about a third at larger budgets). The search budget changes results (see measurement); which budget is the default is undecided.
  (7) Question-level failure typing (L-108 precedence) and the integration of the three tiers (I-16) are not decided; T5 reports per tier.
  (8) N-11: only "no fixed point within the budget" is marked as a place where stacking would occur; the design gives no threshold for "stability collapses" in terms of inv.
  (9) Particle answers: every ANSWER in the run is は (owner: "そのまま組んで測る"); not changed.
  (10) Cost: the whole-space read is about 400-540 s per RUN question in pure Python (incremental evaluation already in); the T5b skip and T5c speed-ups are separate tickets.

- T6 (read-out) open points, nothing below is decided by the code beyond the flagged default:
  (1) Section path with several legs (L-121): a section sees up to three legs, and in the S300 states two or three of them usually end at the same unit. The code reads all legs that reach the pointed unit in ring order (so e.g. section 4 reads "であるのをは"). Alternatives: read only the section's own arm; read each leg as its own path (then more than 6 items would be ordered, N-13's 720 bound would not hold); read the longest.
  (2) Whether the query unit sitting at the outer end belongs to the read path (L-120: not). Including it would put the question words in the answer text.
  (3) Sentence = joined words. Whether the whole path including the repeated end unit is written per section (the code does: the centre は is written k times), or the shared centre once at the end, is a meaning choice; N-13's "whole section paths" was read literally.
  (4) What "candidate" is when two orderings read out identical text (L-123): counted as orderings (k!), listed as one sentence. With k = 6 sections the list is always large (CHOICE): the owner already knew that I-13 + I-15 make every multi-section read-out a list; the measured sizes are in the report (typically 720 per state, 9360 for 13 tied states on RUN).
  (5) All tied adopted states of a question (up to 13 on RUN) are read out and their sentences pooled; the alternative reading is one "the" stable state (not defined when the cycle adopts several seeds at one stability).
  (6) Stability of a sentence is the stability of the state and is the same for all k! orderings; there is no finer stability between orderings, so ordering itself can never produce a single adopted sentence (N-14: "そのまま組んで影響を見る").
  (7) The "too many" limit (20) is only a display value (design L-21); which number the owner wants is open.
  (8) Observation: the read-out words depend on the adopted states, which on S300 are the same few states for almost every question (RUN: 2 distinct content-word sets over 75 read-out questions). Whether the question should shape which paths are read (e.g. read only the sections whose attached query unit is grounded) is open.

- T6v (diagnostic variants) open points, nothing below is decided by the code beyond the flagged option:
  (1) V3: "candidate states" = fixed points of answering members; whether non-answering fixed points (which also have working sections and paths) belong to the pool, and whether the sharing score should be normalised by the state's own sentence count (the raw count favours states made of frequent units: with function words kept it favours hubs) is not decided.
  (2) V3: with ties kept, the pool is huge (median 5310 states, about 1.9M listed sentences on RUN): the lists then contain the gold at the chance rate. A tie rule (e.g. also by stability, then list) is the owner's.
  (3) V1: "contains at least one query unit" counts any seat of the placed cross; 60 of 90 questions then have no adopted state (ratio disagreement / no fixed point / no evidence) because only the crosses of the question's units are read. Whether crosses sharing a sentence with a query unit (design M-2 group 2) should also be read is open.
  (4) V2: the function-word rule is T6's L-130 (UniDic POS), applied also to question words (どこ, 何, ...) and to mixed RUN strings such as 「はどこにありますか」; it removes only 142 of 2175 RUN units but ~4.5 times as many class members appear in the placements (more tied arrangements without the function-word hubs). Whether the rule is the owner's meaning of "助詞を外す" (e.g. keep copula / verbs of 非自立可能) is open. Removing units makes former neighbours adjacent in the word order (L-141): not asked, not decided.
  (5) Strict 0 remains for every variant: I-13 + N-13 (every ordering of 6 section paths is a candidate) and I-15 (one stability per state) make the read-out a list whenever the paths differ; no variant changes that. The cycle's own unit answer (not a read-out) is correct on 3 of 60 for V123 (RUN), 0 for the others.
  (6) Cost: V2 needs its own placements and a whole-space read at about 4.5 times the class members; the full 90 questions were not run.
