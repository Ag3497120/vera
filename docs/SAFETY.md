# Safety: claims, limits, threat model

(日本語の要点は README.md の「測った数字」「限界」。)

## 1. The guarantee, exactly

For `vera ask`, `vera mem` and `vera run` (for a memory answer: whose source sentence is the **user's** own words; an answer quoted from an agent's record is marked 「出所: 利用者の発言ではない（エージェントの記録）」 in the CLI, the UI and the JSON, see limit 4):

> If Vera shows an answer, then there is a successful `emit` row in a ledger that **verifies and replays identically**, and its text is a **verbatim stretch of one sentence** of the corpus (or of a remembered sentence) that the **evidence gate** passed for **this question**. In every other case Vera shows 「分かりません」 and a typed reason.

It is a statement about *what is shown*, not about the model. The model can be wrong, adversarial or prompt-injected; what it can do is limited to calling Vera's tools, and what comes out is limited to the above.

It is **not** a statement that the quote is the right answer (see 3.2), that the record is true, or that the transcript of an agent framework contains nothing else (E2, see 4).

## 2. Claims and where the numbers come from

All numbers are re-measurable offline with `vera eval` (the gate on the shipped banks; the memory red teams on two memories), compared with the frozen record `verantyx/harness/evals/expected.json`, or are reports in the `research` branch.

| claim | number | what it does *not* say |
|---|---|---|
| No answer to an unanswerable question: every stretch of 1 to 10 words of the sentences a question is asked over goes through gate v6; none passes | bank4 (the bank2+4 dev set) 0/60, bank6 0/34, bank7 0/47, bank8 0/50 | not a test on unseen data: bank6, 7 and 8 were used afterwards to examine the rules (bank8 was one unseen judgment, at gate v2) and are now regression sets. A new kind of question may be admitted. The corpus is 592 sentences of encyclopedic Japanese |
| A real model made no confident wrong answer on unanswerable questions | 0/126 | Claude Haiku 5.5, gate v2, one study. Not measured for other models, or for gate v6 with a model |
| The memory made no wrong answer under the research red teams **[research figure]** | 0 | the red teams are the ones we thought of. `vera eval` re-runs four of them on two memories |
| Contradiction detection **[research figure]** | precision 0.83, 137 of 216 planted | detection only (a note), measured on writes a Claude model made in the research meter. **The shipped eval (`vera eval`, two memories, 20 questions) shows less: SAME_SEAT 11 firings, 7 on a planted fact, 4 false alarms, 7 of 12 plants found; UPDATE 0/6 and REVERSAL_X 0/4; 4 of 20 questions answered correctly by quote** |
| Replay | stored ledgers byte-identical | the shipped fixtures replay only on CPython 3.11.14 (CI is pinned to it); ledgers you make replay on your own CPython x.y.z and dictionary-derived hashes |

The research also measured that **the structure did not beat a plain log**: in the memory meter (meter v1, 6 tasks, 3 repeats) a plain log with a model found more planted contradictions (35.0 of 36 against 24.7 of 36) and answered more of the questions (55 of 60 against 17.7 of 60), at about a tenth of the cost. The memory's crosses and nests are kept because they are deterministic, replayable and refuse safely, **not because they are shown to be better**.

## 3. Limits

1. **Japanese only.** An English question is refused by the gate.
2. **The gate does not know the right answer.** On answerable questions it passes a stretch whose clause fits the question; some such stretches are not the gold answer (`vera eval`: in bank6, 3 of 26 answerable questions, and in bank8, 1 of 35, have a non-gold stretch admitted). A model that picks that stretch shows a quote that is verbatim, from the right sentence shape, and still not what you asked.
3. **Low reach.** About one answerable question in ten reaches a quote (dev 10/69, bank6 3/26, bank7 1/32, bank8 3/35). This is a **gate-only sweep with no model** over the dev and held-out-at-the-time banks, not a reach with a model and not a measurement on unseen questions. The harness is useful when silence is cheap and a wrong answer is expensive.
4. **Memory writes are the user's words.** In `vera mem` and the UI every user message is a `user_turn` row (with its text) in the hash chain; a model `write` / `keep_unshaped` runs only if its text EQUALS one whole sentence (split ONLY after 。！？ or at the end of the message; a line break is not a boundary and stays inside the sentence, so 「山本\nではありません。」 is one sentence that no clean write equals; NFC; a final 。 optional) of the user message of the turn being delivered, never a piece of a sentence (a piece can invert it: 「山本ではない」 → 「山本」), else it is refused `not_from_user` (a `write_refused` row) and never stored; `vera verify` re-checks every stored write against the user turn it was written in, and flags a write before the first user turn (`WRITE_NOT_FROM_USER`). A write's time is that user turn, which the model cannot name, so re-quoting an earlier message cannot make an old statement look newer. The memory's own one-fact-per-write coverage rules then decide whether the sentence can ever be an answer (a negation, a question, a condition or a quotation does not). MCP memory sessions have no user turns: their writes are the agent's claims, reported as `unsourced_sessions`; **an answer quoted from such a sentence carries the mark above** (CLI, JSON, UI and the MCP question-phase `emit` result: `sourced`, `mark`). **One rule: an agent's (unsourced) write never takes part in ordering or retirement.** Its rows carry no turn (a `turn` argument is stripped; `report` cannot set one); a `supersede` runs only if its new side is a user-sourced sentence and every retired sentence is user-sourced and from a strictly earlier user turn, otherwise it is refused `unsourced_order` (a `supersede_refused` row), whichever session issues it; an agent's write that reads as a change (「…に変更」) is refused (`unsourced_order`); `verify` re-checks all of it in every session (`UNSOURCED_ORDER`). An agent's value may CONTEST a user's value (the position becomes ambiguous and the memory abstains, with the mark on any quote of it) but never answers over it; consequently a later user correction of an agent's record is also contested, not applied. The research entry `python -m verantyx.loom.memmcp` has none of these guards and refuses to start without `--research-unguarded`.

   **The recorded user turns are the source of truth; the model's writes only select from them.** At every memory answer (and in `verify`) every sentence of every recorded user turn is read with the memory's own reader: if one says something else at the answered position and is not a stored write (the model left it out, or the memory refused it), the answer is refused `unrecorded_user_statement` (with the turn; a `statement_refused` row, no emit) and `verify` reports `USER_STATEMENT_NOT_RECORDED` for an answer run that emitted anyway. The check is conservative: it ignores nest scopes. A store whose `verify` is not OK answers nothing (`store_not_verified`: CLI, UI, MCP question phase). Secret-shaped spans of a user message are replaced by `[redacted:sha256-8]` before anything is recorded or read; the marker and its `key=` label are not part of what the user said and are taken out before reading, so a correction in the same sentence is still read. After a secret label the whole ASCII run is redacted whatever its length (`password=hunter2` too; `!` and `?` are part of the value). **Normally a redaction costs only the span. In the lossy case it costs more, by design:** if the redaction removed or changed a sentence boundary, erased a whole sentence (「secret: …。」), or had to drop the whole message, the turn is recorded `redaction_lossy` and every later ask whose answer was said in a turn not later than it is refused `redacted_turn_unreadable` (a `statement_refused` row; also on every contested-refusal path, so no list of values is shown as the live conflict; `verify`: `REDACTED_TURN_UNREADABLE`); the `say` result, the CLI and the UI tell the user that part of the message was redacted and could not be read. A contested list never presents a value that a later user sentence replaced as current: the answer becomes `unrecorded_user_statement` and each such value is shown as replaced. In a contested list every value carries its own `sourced` flag and the mark if unsourced (CLI, JSON, UI, MCP `recall`).

   **Self-corrections inside one message.** Exactly two things make a position `ambiguous_in_turn` (no write for that position is accepted from that message; a `write_refused` row; `verify` re-checks: `AMBIGUOUS_WRITE`): two sentences of the message that the memory reads at the same position, or a sentence the memory cannot read placed right after a readable fact. Other ways of correcting oneself are **a reader-coverage limit, not a guarantee**: if the correction is itself a readable sentence at another position or in a form the reader takes as a different place (「広報の担当は山本。広報担当は鈴木です。」, 「…。訂正します、広報の担当者は鈴木です。」, 「…。それは先月までの話で、今は鈴木です。」, 「経理は佐藤。…。ごめん、最初のは鈴木の間違い」 with another sentence in between), the first fact is stored and the correction may not be. This over- and under-refuses by nature. Also a 「？」 splits a condition off its consequence (「もし予算が通れば？広報の担当は鈴木。」 stores the second sentence as a plain fact). Facts separated only by line breaks, without 。, are one sentence: end each with 。. Say each fact once, in one sentence.
5. **The memory answers only from one-fact-per-write sentences** of the forms its shape table reads (「X の Y は A」 and a few more). Not read: a change expressed in words the table lacks, extension, 「X は Y が担当」, synonyms, a retraction in another write, the value of an event sentence (the question is read, the value is not quoted).
5. **Real-model evidence is Claude Haiku 5.5 only.** Other backends are tested with fake clients. A weaker model should produce more silence, not more lies; that is expected but not yet measured.
6. **Replay is exact-environment.** The header names the CPython x.y.z and the hashes of the tokenizer-derived tables; a different environment gets `INPUTS`.
7. **Quoted text is the record's.** If a document is wrong, outdated or hostile, a correct-looking quote of it passes.
8. **Privacy.** With a cloud backend, your questions and every sentence the model looks up or reads are sent to that provider. Use a local backend (Ollama, LM Studio, vLLM, MLX) to keep them on the machine.

## 4. Enforcement levels

| | scope | guaranteed | not guaranteed |
|---|---|---|---|
| **E1** `vera ask/mem/run` | the harness drives the model through an API | only Vera's tools are offered; free text is dropped (hash + length); an unknown tool name is rejected with no state change; the person sees only a verified `emit` | the model's host (a provider, a local server) is outside the harness |
| **E2** `vera mcp` + Claude Code subagent allow-list | the agent's tools | the agent can call Vera's tools only; `vera loom output` prints only a verified `emit` | the **transcript still contains what the agent wrote**, and Vera cannot stop a parent agent or a person from reading it as the answer. Take the answer from the ledger. The allow-list is Claude Code's, not Vera's |
| **E3** `vera loom mcp --isolated` (macOS) | the MCP server process | OS sandbox (`sandbox-exec`): no network, no fork/exec, reads and writes only in listed places; a probe under the same profile must pass first, or exit 3 | the client is not confined; Apple has deprecated `sandbox-exec`; Linux bubblewrap is not implemented |

## 5. Threat model

Assets: the reader's trust in a shown answer; the documents and the memory; API keys; the local machine; the ledgers.

| threat | what Vera does | residual |
|---|---|---|
| The model hallucinates or is adversarial | forced tools; free text dropped; quote-only output; the gate refuses by default; caps stop loops; refusals are typed rows | limits 2 and 3 |
| Prompt injection in a document or a remembered sentence | the document reaches the model only as tool results; whatever the model is told to do, it can only call Vera's tools, and the output stays a gate-passed quote of the record | an injected sentence that *has the shape of an answer* can be quoted as one (limit 8). The harness cannot tell a planted fact from a true one |
| A ledger is edited afterwards | row hashes and links (`TAMPERED`), canonical form, torn tail, the `HEAD` pin, replay (`REPLAY_DIFFERS` catches a forged result) | someone who can rewrite the *whole* folder can rewrite the whole chain: pin `HEAD` elsewhere. `harness.json`, `timing.jsonl` and `runs/_corpora` are outside the chain (the corpus is bound by its sha256 in the `begin` row) |
| A website attacks the local web UI (`vera run`) | binds loopback only (127.0.0.0/8, ::1; there is **no** `--allow-remote` in this version: it is refused); the base URL, the key environment-variable name, the documents and the storage folders can be set **only on the command line** (the page shows them read-only, so a token holder cannot point the backend or a secret's name anywhere); every `/api/` call needs a per-process token that only the served page holds; POST must be `application/json`; an `Origin` must be this origin; the `Host` header must be a loopback name with the server's port (DNS rebinding); **no CORS headers**; CSP `default-src 'none'` with the page's own inline script and style allowed by hash and `connect-src 'self'`; `X-Frame-Options: DENY`; no external loads; one run at a time; 64 KB request bodies; answers and sentences are rendered as text, never as HTML; the trace shows model-chosen strings only as `sha256-8/length`, API error text is replaced by the exception class and a fixed message (a server can echo raw model output in it), and the server's claim of which model ran is shown as unverified unless it matches the requested one | **another process on the same machine can connect to 127.0.0.1, read the page and therefore the token, and use your configured backend** (and spend its credits). There is no per-user authentication: treat the UI as trusted-local. On a shared machine do not run it; use the CLI. Remote access is not offered. |
| Keys leak | keys come only from the environment or the macOS Keychain, are resolved at call time and handed to the SDK client only; every error text is passed through `redact`; `--base-url` with credentials is refused (the run folder records the URL); the UI shows presence and source, never a value, and has no field that accepts a key (the "key environment variable" field takes a *name* and rejects anything else) | keys in the environment are visible to your other processes; a Keychain read may prompt (only the `vera-harness` item is read; the research tree's `vera-loom` item is not);  a provider's own logging is out of scope |
| A malicious plugin | it can only refuse (gates), pick Vera-implemented versions (memory profiles), show notes (note kinds) or supply a backend; a gate-filter refusal is a `plugin_refused` row in the ledger and the run closes with an `abstain` (no emitted output exists, `vera loom output` prints nothing); the ledger records each plugin's name, version and a sha256 of the source of its entry-point module, and a missing plugin, another version or other code makes verify say `INPUTS` | **a plugin is arbitrary Python running with your privileges** (an entry point is code); the digest covers the entry-point module's own file, not everything it imports. Install only code you trust |
| Dependency or data tampering | the tokenizer and its dictionary are pinned in CI (`.github/constraints.txt`); the shipped eval files are checked against `MANIFEST.json` before every `vera eval` | a compromised release of a dependency |
| Resource exhaustion | caps on repeated operations, status calls and turns; one run at a time in the UI; a request-size limit | a very large corpus is read into memory |

## 6. Out of scope

The truth of your documents; the confidentiality of what you send to a cloud provider (3.9); a model host you do not control; side channels of the machine; the transcript of agent frameworks other than as described for E2.

## 7. Reporting

Open an issue, or write to the maintainer privately, for anything that lets an answer out that the gate should have refused, or lets a web page reach the local server.
