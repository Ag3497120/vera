# Vera Harness の説明（vxrt のテストハーネスを考えるセッション向け）

書いた人: Vera セッション（2026-10-14）。目的: vxrt に「AI が自分でゲームを起動・計測し、結果を構造化データで受け取る」仕組みを作る際に、Vera Harness が使えるか、何が流用できるかを判断する材料。

## 1. Vera Harness とは

- 置き場所: GitHub `Ag3497120/vera` の `vera-harness` ブランチ（作業中。中核の切り出しとモデルの差し替えまで済み、CLI は作成中）。設計は `line3` ブランチの `docs/HARNESS_DESIGN.md`。
- 一言で: **モデルの出力を、決定的な検証層を通したものだけにする「検証のハーネス」**。モデル（Claude、OpenAI 互換の DeepSeek・Ollama など）は Vera の操作（調べる・引用する・出す・棄権する）しか使えず、自由な文は捨てられる。
- 中核は Python 標準ライブラリ＋形態素解析（fugashi）だけ。学習なし、オフライン、同じ入力なら同じバイト列。

## 2. 仕組み（REA の 4 点との対応）

| REA の強み | Vera Harness で対応するもの |
|---|---|
| AI が必要なときに自分で道具を呼ぶ | MCP サーバー（`vera mcp`）と API 駆動部。AI は調べる・読む・引用する操作を自分で呼ぶ。道具以外の出力は捨てる（強制） |
| 結果が決まった形のデータ（事実・導出・推測・不明、範囲と限界） | 答えは「記録の一字一句の引用＋出所」か「型付きの棄権」（根拠なし・食い違い・古い値・未確認）だけ。台帳の各行に何を見て何を判断したかが残る |
| 検証の段階が決まっている | 事前に凍結した基準、未見の問題集は 1 回だけ使う、敵対的な審査を通るまで取り込まない、CI で 3 種類の乱数設定と台帳の再生がバイト一致 |
| 手順書とセットアップ | CLAUDE 用のサブエージェント定義（使える道具の許可リスト）、OS サンドボックスの設定。手順書（skills）としての整備はこれから |

加えて Vera にあって REA にないもの:
- **ハッシュで連ねた台帳と再生**: 実行のすべての操作が記録され、誰でも `verify` / `replay` で同じ結果を再現できる。
- **既定で拒否**: 主張は、根拠になる記録を一字一句指せたときだけ通る。それ以外は「分かりません（理由）」。

## 3. vxrt にそのまま使えるか（正直な判断）

**そのままは使えない。** Vera Harness の「証拠の門」は日本語の文を節まで読んで引用を判定するもので、fps・例外数・画面が黒いかといった計測値は扱えない。ゲームの起動や SteamVR の操作もしない。

**流用できる部分はある。** 特に 2 と 3 は、vxrt の「推測と事実が混ざる」「-vr を付け忘れた実行を回帰と誤認しかけた」問題にそのまま効く。

1. **台帳の形式と verify / replay**（`verantyx/loom/ledger.py`）: 言語に依存しない。各実行（起動引数、環境、出力ファイルの sha256、計測値）をハッシュで連ねて残し、後から改ざんなしを確かめられる。
2. **主張は証拠つきでしか出せない規則**: 結果 JSON の各項目に「観測（成果物のパスと sha256 付き）／導出（どの観測から）／推測／不明」の区分を必須にし、観測の裏付けがない数値を「回帰」「達成」と書けないようにする（Vera の門の考え方を数値に移したもの）。
3. **前提条件の型付き拒否**: Vera は条件を満たさない問いを判定せず拒否する。同じく `vxrt_run` は「-vr がない」「ユーザーがプレイ中」「SteamVR が別フォルダで起動していない」を検出したら、計測せずに型付きの理由で止める。
4. **MCP の公開と強制の段**: 道具の許可リスト、出力は道具経由だけ、という作りはそのまま参考になる。
5. **進め方**: 基準値の凍結、未見の確認、敵対的な審査、CI のピン留め（Python の版まで台帳に記録して一致を要求）。

## 4. 結果 JSON の例（提案）

```json
{
  "run_id": "2026-10-14T10:20:03Z-alyx-3k",
  "preconditions": {"vr_flag": true, "user_playing": false, "steamvr_isolated": true},
  "observed": [
    {"metric": "fps_p50", "value": 58.7, "artifact": "runs/…/frametimes.csv", "sha256": "…"},
    {"metric": "exceptions", "value": 0, "artifact": "runs/…/stderr.log", "sha256": "…"},
    {"metric": "black_frame", "value": false, "artifact": "runs/…/frame_0300.png", "sha256": "…"}
  ],
  "derived": [{"claim": "below_baseline_60fps", "from": ["fps_p50"], "baseline": "baselines/alyx_3k.json"}],
  "inferred": [{"claim": "GC スパイクの疑い", "basis": "frametimes の 200ms 超が 12 回", "confidence": "low"}],
  "unknown": [{"item": "未実装関数 87 個のうち実行時に呼ばれたもの", "reason": "呼び出しトレース未取得"}],
  "scope": {"duration_s": 120, "scene": "intro"},
  "limits": ["Rosetta 下のため lldb なし、呼び出しトレースで代替"],
  "ledger": {"head": "…", "verify": "OK"}
}
```

`derived` と `inferred` は `observed` の項目を参照しない限り書けない、`unknown` は「調べていないこと」を必ず列挙する、という規則を検証側で強制すると、推測と事実が混ざらない。

## 5. 勧め

- vxrt のテストハーネス（`tools/vxrt_run.py`、`make vr-check`、MCP）は vxrt 側で作る。その際、上の JSON の区分と「前提条件の型付き拒否」を最初から入れる。
- 実行記録の改ざん検知と再生が欲しくなったら、Vera の `ledger.py` を依存として使える（言語非依存、標準ライブラリのみ）。必要なら Vera 側で切り出して小さなパッケージにする。
- 日本語の証拠の門と記憶の構造は vxrt には不要。
