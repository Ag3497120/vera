# F2 — 1 つの単位にならない答えを、粒度（RUN / WORD / CHAR）の間の接続で組む

状態: 設計＋実装（`verantyx/line3/granularity.py`、既定オフ）。判断点は L-480〜（docs/LINE3_LOCAL_DECISIONS.md の「## F2」）。
オーナーの決定（ops/decisions/2026-10-06_line3_faithful_build.md「T9（bank2）の監査後の決定」、逐語）:
「そのために様じまな粒度での接続があるのでそれを使って」。対象は bank2 intra2 の正解 69 問のうち 1 つの単位にならない 18 問
（ハッシュ表 → ハッシュ／表、カール・マルクス → カール／マルクス、3万2,500キロワット → コンマで割れる、…）。

## 1. 「粒度の間の接続」とは何か（出典つきの読み）

仕様のどこにも「段と段のリンク」を別の表として定めた箇所は無い。あるのは次の事実で、接続はそこから出る。

| 出典 | 内容 |
|---|---|
| 決定 2「複数の粒度を段に並べる」、I-01、LINE3_DESIGN §3.1、L-03 | 3 段（RUN / WORD / CHAR）は**同じ文**を 3 通りに切ったもの。RUN = 内容の塊＋塊のあいだの文字列、WORD = UniDic 短単位、CHAR = 1 文字。句読点・記号はどの段も単位にしない（L-32） |
| I-16、I-25、L-212 | 段は別々に回し、段をまたいで足さない・混ぜない |
| L-220（T7b）、決定「全段の候補を段の印つきで並べる」 | 利用者には全段の候補を段の印つきで見せる。段どうしの票は足さない |
| L-213 | 段のあいだの一致は**報告のみ**（共通の語・中心）。選択・加点に使わない |
| `Space.trace`（L-34 周辺）| 単位 → それを持つ文（sid）。出典の逆引き |

したがって「接続」＝**同じ文の中で、異なる段の単位が占める表層の範囲（span）の包含・隣接**。RUN の単位は WORD の単位を含み、WORD の単位は
CHAR の単位を含む（各段が捨てる語・記号の分だけ欠ける）。範囲は文を再び切って文字位置で出す（L-480）ので、出典（sid と文字位置）がそのまま付く。
これは L-213（報告のみ）より一歩進んで、段をまたぐ情報を答えの**組み立て**に使うが、**選択・採点・加算には使わない**（L-212 を破らない）。

## 2. 答えの組み立て方（最も字義どおりの読み）

入力: 利用者に見せる候補の列（`Combined.entries` = (段, 語の集合, 出典 sid)）。

1. 各候補の語が、その候補の出典の文の中で単位として現れる位置（出現）を取る。出現 = (段, sid, 文内の番号) と範囲 [start, end)。
2. 同じ文の出現を、範囲が**重なる、または接する**ものどうしでつなぐ。「接する」＝間に文字（文字・数字・記号付きの文字 L/N/M）が無く、
   どの段も捨てた文字（Unicode L/N/M 以外の全て: 「・」「,」空白のほか「、」「。」「（」「）」「「」「」」も）だけが挟まる。間に捨てられていない文字（助詞など）があればつながない（bridge=False、OP-F2-2）。
3. つないだ範囲が、既にある 1 つの単位そのもの（どれかの出現が全体を覆う）なら新しい候補ではない（重なっただけ）。そうでなければ
   **組み立てた文字列**（文の [start, end) の表層。間の「・」「,」も表層として残す）。
4. その文字列の範囲を各段に当て、**両端が単位の境目で、範囲内の文字が全てその段の単位に覆われる**段を `aligned_tiers` に挙げる。
   一番粗い段（RUN → WORD → CHAR）が `lifted_tier`（その文字列を「単位の列として持つ」最も粗い粒度）。
5. スコープ（OP-F2-1）: `entry` = 候補 1 つの中だけ（その候補の段の単位だけ）、`all` = 同じ文を指す全段の全候補の出現を寄せる（段をまたぐ接続）。
   既定は `all`（粒度の間の接続を使う、というオーナーの言葉に最も近い）。

例: ハッシュ表（文「ハッシュ表ともいう。」）。RUN の候補 {ハッシュ, 表} → 範囲 0-4 と 4-5 が接する → 「ハッシュ表」、部品 RUN:ハッシュ + RUN:表、
`aligned_tiers` = RUN, WORD, CHAR。カール・マルクス → RUN:カール + RUN:マルクス が捨てられた「・」を挟んで接し「カール・マルクス」。
3万2,500キロワット → RUN:最大3万2 + RUN:500キロワット が「,」を挟み「最大3万2,500キロワット」。WORD の候補「ハッシュ」と RUN の候補「表」のように
**段が違う候補**でも、`all` なら同じ文の接する範囲としてつながる（部品に段が残る）。

## 3. 利用者に見せるもの

組み立てた文字列は**追加の候補**として、部品（段・単位・文字位置・どの候補から来たか）と `aligned_tiers`・出典文付きで見せる。元の候補（部品）は
置き換えず、並べ替えず、消さない（L-485）。`answer` の下に `assembled` が付くだけで、オフなら出力は 1 byte も変わらない。テキストでは「つなげた候補 N 件」
の下に 1 行ずつ。文字列の順は (sid, 開始位置, 終了位置)。件数の上限は設けない（N-20）。順位・安定度は付けない（段をまたいで足さない）。

## 4. 追跡できること

組み立てた文字列の全ての文字は、(a) 出典の文（sid）の [start, end) の文字、かつ (b) ある段のある単位（部品）が覆う文字か、どの段も単位にしない
文字（間の「・」「,」）。`trace_check` が文の文字列と各段の単位列だけを使って（SpanIndex も切り直しも使わない。bridge=True のときだけ組み立て側の機能語の範囲を使う）、文字列＝文の範囲、各部品＝その段のその番号の単位＝範囲の表層で、その番号の位置にあること、範囲内の文字は全て部品に覆われる、
部品どうしは捨てられた文字だけを挟んで連なる、を確かめる（実験側の道具ではなくテストで全件に使う）。

## 5. 未決の判断点（オーナーへ）

- **OP-F2-1 スコープ**: `entry`（1 候補の中だけ）か `all`（全段の全候補を寄せる）か。T9 の 18 問では平坦・path 層でどちらも同じ 4 問、層（seatsPath）で 11 対 12。
  `all` は件数が少し減る。段をまたぐ接続を使う、の読みで `all` を既定にしたが、「候補ごとに別」と読むなら `entry`。
- **OP-F2-2 隣接の定め**: 捨てられた文字だけを挟む場合のみ接する（既定）か、間に機能語（の・から）があってもつなぐか（`bridge=True`、実装済・既定オフ）。
  bridge は上限を 14/18 → 18/18 にし、「路線の廃止」「キューバの太陽」型を拾うが、組み立て文字列が長くなる（実測は §6）。
- **OP-F2-3 切り詰め**: 組み立てた文字列は部品の外周そのまま（「最大3万2,500キロワット」）。正解の境目で切り詰めるには正解が要るので行わない。
  「一番細かい段の鎖」だけを出す読み（CHAR の連なり）や、`lifted_tier` の段の単位列だけを出す読みは作っていない。
- **OP-F2-4 対象の文**: 候補の出典 sid 全て（既定）。層の候補は出典が文の約 85 %（T9 audit）に及び、文字列が候補あたり 1700 件規模になる（§6）。
  「候補の語を 2 つ以上含む文だけ」「最も語を含む文だけ」に絞る読みは作っていない。
- **OP-F2-5 正解の判定**: 組み立てた文字列に正解が部分文字列として入れば当たり、とするのは長い文字列に甘い。実測は余分な文字数（excess）と対照（他の問いの正解を当てる率）を併記した。
- **OP-F2-6 L-213 との関係**: 段の一致を報告するだけという L-213 は変えていない。組み立てが段をまたいで情報を使う点が L-213 の「使わない」を越えていないか（選択に使っていないので越えないと読んだ）。
- **OP-F2-7 入口**: CLI の `--granularity` は layer 0 の候補にだけ付く（層の候補には付けない）。層の候補にも付けるかは未決。

## 6. 測定（experiments/line3/f2/measure.py、結果 results.txt。T9 audit の記録の再生）

L-490〜に記録。要点: 1 つの単位でない 18 問の正解は、正解の文の 3 段の単位から全て組める（隣接＝捨てた文字のみ）のは 14/18（bridge ありで 18/18）。
T9 の標準の出力（候補と出典）にオプションを当てると、平坦と path 層では 4/18（excess 0,0,0,2）、層 seatsPath では 11〜12/18 だが 1 問あたり 1700〜2200 件の文字列で、
他の問いの正解を当てる対照が 28 % ある（自分の正解 12/18 は対照より高いが、2000 件規模の並びの中では答えを選び出せない）。
平坦・path の 4 問はどれも 1 つの段の単位の隣接（RUN カール＋マルクス 等）で、段をまたいで寄せる効果は平坦・path で 0、seatsPath で 1 問（R2-I008、「（）、」越し）。
