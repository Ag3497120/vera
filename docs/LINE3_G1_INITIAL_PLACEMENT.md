## 2. 今の「初期配置」（事実）と、人為的な配置が入る場所

### 2.1 今のコードがしていること (O: コードを読んだ)

1. **空間**（`space.py`、L-150）: 既定で機能語・疑問語は単位でない（`funcwords.is_function_unit`）。fulllead_sents（592 文）で単位の数は、機能語を残すと RUN 3935・WORD 3780・CHAR 1429、既定（外す）で RUN 3653・WORD 3557・CHAR 1358。**F1 の十字には助詞が 1 つも無い**。
2. **十字の出発点**（`placement.build_cross`）: 種の語だけを中心に置く（L-63、L-77。中心の空いた並びは状態でない）。
3. **足す順**（M-1(b)、L-63）: 種と共有する文の数 n(seed,v) の大きい順の群。同じ数の群は、既定 `whole` では一度に（L-72）、`ordered` では種の posting の文順・文中の初出順に 1 つずつ（L-460/L-461）。崩れた（予算超え）語の直前で止める（L-463。F1c の `skip` は飛ばして続ける）。
4. **安定**（I-04、L-70/L-71）: 鍵 =（辺の n(x,y) の和、外→内の辺の p(x,y) の和）の辞書式。同じ鍵の並びは 1 つの類として持つ。1 手（23 回転＋2 席の入れ替え）で良くならない類が安定。
5. **エネルギー**（`energy.py`）: r0(v) = n(v)/N（I-06）、E_Q(v) = r0(v) + Σ_q n(q,v)/N（N-01）。**r0 は配置の鍵に入らない**（LINE3_DESIGN §3.4）。問いの周期の 3 つの比率（断面の歩き、辺の流れ F、配置の結び B）でだけ使う。
6. **観察記録**（L-67/L-20）: 読んだ十字の各単位の r0・E_Q・E_Q/r0。

つまり今の「初期配置」は、**種 1 語＋文の語順＋データから数えた比率**であり、人の手で決めた部分は無い。

### 2.3 人為的な初期配置が入る場所 — 字義どおりの読み（全て）

「初期の基盤からデータを入れるだけで…成長」の「基盤」が、今の構造のどこに入るかは言葉から一つに決まらない。読みは 4 つある。

## 3. 設計

### 3.1 (a) 機能語の基盤十字

#### 3.1.1 何を「基盤」とするか

基盤 F = (U_F, r_F, 位置の規則, 付着の規則)。

- **U_F**: 人の手で書いた機能語の一覧（作られた単位、kind = `constructed`）。データの空間（T6v の既定）には入れない（T-3）。
- **r_F**: U_F の各語に人の手で与える比率。厳密な分数（L-02）。これが「黄金比率」の数の部分（§3.1.3）。
- **位置の規則**: r_F から席を決める（I-06 前半「エネルギー比率を与えておくなどで初期整合位置を決めておいて」）。
- **付着の規則**: データの語が基盤の語にどう繋がるか（§3.1.5）。データから数える整数で、証拠の量 n とは別に持つ。

候補（初期の最大の一覧、最小化はここから削る。§3.4）【推奨】:

| 名前 | 語 | 根拠 |
|---|---|---|
| P7 | は、の、に、を、が、で、と | 3 段とも助詞の上位 7（§2.4 (1)）。I-03 の中心＋6 腕に数が合う |
| P12 | P7 ＋ から、も、など、や、より | WORD の次の助詞 5 つ（57・50・33・31・18）。中心が種（OP-G1-2 (a)）なら 1・2 環目の 12 席に合う |
| P13 | P12 ＋ まで（14） | 中心が基盤の語（OP-G1-2 (b)）なら 13 席に合う |

助動詞・活用語尾（た、て、し、ある、する、である、される）は入れない【推奨】: オーナーの言葉は「助詞などで組む」で、これらは延べで多い（WORD た 199・ある 187）が、付ける先が語でなく文の述部になる。入れる読みは最小化の候補一覧に足すだけで試せる（G1-g の選択肢）。

#### 3.1.2 席の数

I-03 の十字は中心＋6 腕×L 席。L=1 で 7 席、L=2 で 13 席。

- **中心をデータの種にする**【推奨・OP-G1-2 (a)】: 中心は種（データの語）のまま（I-02、L-77、T6w「中心は参考」を保つ）。基盤は 1 環目（各腕の中心側の席 k=L−1）に 6 語、2 環目（k=L−2）に 6 語。P7 は 7 語なので、r_F の 7 位が 2 環目の 1 席に入る。基盤の席は 6・12。
- 1 つの腕に作られた席が 2 つ並ぶと、1 環目の語は中心と 2 環目の席にしか隣り合わず、データの語と隣にならない。また腕ごとにデータの席で作られた席の隣になるのは一番内側の 1 席だけなので、「隣の作られた席」で付着を数えると、1 つの十字で a > 0 になれるデータの語は最大 6 つになる。このため付着は「隣」でなく「同じ腕」で数える【推奨・OP-G1-9 (a)】（§3.1.5）。
- 中心を基盤の語（は）にする（OP-G1-2 (b)）: 基盤は 7・13 席にぴったり合う。種とデータは腕に乗る。中心が作られた単位なので、3 つの比率の一致は腕の上のデータの語だけで測る（§3.1.6）。

データの席: L は L-65 のまま「6L+1 ≥ 席に着く語（基盤を含む）」の最小。L が増えると外側に空席が足され、基盤の席は中心から数えた環の位置に留まる（データは基盤より外側に育つ）。

#### 3.1.3 比率（黄金比率）を人の手で決める

満たすべき条件（言葉と既存の規則から導ける）:
1. 厳密な分数（L-02。φ=(1+√5)/2 そのものは使えない）。
2. **互いに異なる**（同点は棄権、順序で勝者を作らない。同じ比率の 2 語は位置が決まらない）。
3. 位置は比率で決まる: 比率が大きいほど中心に近い環、同じ環の中では比率の順に腕の名札 1〜6 を付ける（腕そのものは L-61 で区別されないので、名札は付着でだけ効く）。

候補の表（OP-G1-3）:

| 案 | 比率 | 中身 |
|---|---|---|
| (a) フィボナッチの梯子【推奨】 | 順位 k（1〜12）に r_F = F(14−k)/F(14) = 233/377、144/377、89/377、55/377、34/377、21/377、13/377、8/377、5/377、3/377、2/377、1/377 | 隣り合う比がほぼ φ（233/144、144/89、…）の厳密な分数。順位は作成者が決める。既定の順位は fulllead の WORD の文の割合の順（は、の、に、で、と、を、が、から、も、など、や、より） |
| (b) 作った時点の文の割合を凍結 | r_F(p) = n(p)/N を基準のコーパスで数えて固定（例 WORD: は 446/592、の 399/592 …） | I-06 後半の式を作成時に一度だけ使い、その後データを足しても変えない |
| (c) オーナーが表を書く | 任意の厳密な分数 | 条件 1・2 を検査で強制 |
| (d) 一様（対照のみ） | 全て 1/|U_F| | 条件 2 を満たさないので位置が決まらず、腕の名札が無い。「比率なしの基盤」の対照として測るだけ |

比率が効くところ（3 か所だけ。これ以外では使わない）:
1. **位置**（上の条件 3）。
2. **付着の重み**: データの語 v が基盤の語 p の席の隣に座ると、付着 a に r_F(p)・adj(v,p) を足す（§3.1.5）。作成者の比率が、データがどの関係（どの助詞の腕）に育つかを決める。
3. **観察**: 作られた語は空間に posting を持たないので、その E_Q は問いによらず常に r_F（変化 0）。N-02「そこからそのエネルギー比率がどうなるかを観察」は**腕の単位で**取る【推奨・L-G1-9】: 腕ごとに (r_F(その腕の作られた語), Σ_{その腕のデータの語 v} (E_Q(v) − r0(v))) を記録し、問いのエネルギーがどの関係の腕に流れ込んだかを見る。データの語ごとの r0・E_Q・比（L-67）は今のまま。

#### 3.1.4 基盤の配置そのものの安定

- 基盤の席は**固定**【推奨・OP-G1-4 (a)】: 「基盤の席に触れる入れ替え・挿入は手でない」（L-77「中心を空ける入れ替えは手でない」と同じ形）。回転は手のまま（全体が回るだけで鍵は不変）。こうしないと、データの入れ替えで作成者の並びが崩れ、「意図する方向」が残らない。
- 基盤は**継ぎ目**（透過）: I-04 の鍵の n・p は、作られた席を縮めた十字（作られた席の両側のデータの語を隣とみなす）で数える。作られた単位は空間に posting を持たないので（L-52 なら n=0 で全ての辺が「未実証」になり、歩きが止まる）、縮めないと十字が働かない。
- 基盤だけの初期状態（種＋基盤）が安定かは、縮めた十字では種 1 語の十字と同じ（鍵は (0,0)）なので自動的に満たされる。M-1(a)（安定の定義で探す）は、データの席に対しては今までどおり当てる。基盤の並びまで探索で動かす読み（OP-G1-4 (b)）では、作成者の並びは出発点にすぎなくなる。

#### 3.1.5 付着と、データの入れ方（F1 の規則がそのまま効く）

**付着 adj(v,p)**【推奨・L-G1-1/L-G1-2】: 文の中で、データの語 v の表層の直後に助詞 p が来る文の数（右付き。日本語の助詞は前の語に付く）。数えるのは WORD の区切りの助詞の出現で、v の span の終わり＝助詞の span の始まり（F2 の SpanIndex、L-480 を使う）。RUN の間の文字列「にある」のような単位も、中の WORD の「に」で数えられる。整数で、文の番号（sid）と span を必ず持つ。左右両方を数える読みは L-G1-2 の選択肢として測る（延べで 29 % → 48 %、§2.4 (3)）。

**鍵**【推奨・OP-G1-5 (a)】: 配置の鍵を (n, p, a) の辞書式にする。n・p は縮めた十字の I-04（今と同じ値）、a = Σ_{データの語 v} Σ_{v と同じ腕の作られた語 p} r_F(p)・adj(v,p)（厳密な分数。OP-G1-9 (a)「腕＝関係の札」: 腕の全てのデータの席が、その腕の作られた語（1・2 環目の 1〜2 語）に付着で結ばれる）。別の読み（OP-G1-9 (b)）は「作られた席の隣のデータの席だけ」で、上の 2 つの帰結（1 環目の語が効かない、a > 0 は十字あたり最大 6 語）を伴う。a は n・p が同じ並びの中でだけ順位を付ける。つまり**今の安定の定義で区別できたものは何も変わらず、今同点だった並び（F1 で RUN 1792 本、WORD 1953 本の十字を max_class で止めている、§2.2）だけが付着で分かれる**。

**入れ方**: M-1(b) の群の順（種との文の共有が多い順）、F1 の群の中の順（L-461）、1 つずつ入れて落ち着かせる（L-460）、崩れたら直前（L-463）または飛ばす（F1c）、は全てそのまま。変わるのは、挿入の得点（L-64）と落ち着かせ（L-71）が (n,p,a) で比べることと、基盤の席が空席でないこと（挿入の先にならない）だけ。

#### 3.1.6 問いの周期で基盤がどう見えるか

- **3 つの比率**: 縮めた十字（作られた席を除いてつないだもの）で、今の `energy.three_ratios` をそのまま計算する。作られた単位は断面の歩きの終点にも、R2・R3 の最大にもならない。**作られた単位は答えにも中心の参考にもならない**（T6w の答えの形は経路の語。経路から作られた語を除く）。
- **関係の名札**: 答え・候補の経路に、各データの語が座った腕の基盤の語（例「の」）を「関係の名札（constructed）」として添える。採点・選択には使わない表示だけ。
- 問いの付け方は I-07 のまま（語順で 6 本の腕の外端）【推奨・OP-G1-8 (a)】。問いの語の直後の助詞が p なら p の腕の外端に付ける、は別の読み（OP-G1-8 (b)）。
- F1c との関係: `on_collapse="skip"` は付着と独立に使える。G1 の測定は F1 の `stop` を主にし、F1c が既定になればそれに合わせる。

#### 3.1.7 「初期作成者の意図する方向」を操作として定める

言葉「初期の基盤からデータを入れるだけでモデルの初期作成者が意図する方向に…成長」を、次の 3 つの観測できる性質として定める【推奨】:

1. **育つ方向＝関係の腕**: データの語は、付着の重い助詞の腕に座る（鍵 a、OP-G1-9 (a) なら腕のどの席でも）。作成者が U_F と r_F を選ぶことで、どの関係（「X の Y」＝の、「X は Y」＝は、「X に Y」＝に …）にデータが集まるかが決まる。測る量: 基盤の各腕のデータの席の数、a > 0 で座ったデータの語の割合。
2. **安定する経路**: 種（中心）→基盤の語→データの語、という経路が、縮めた十字の辺として実証される（n > 0）ときに断面の歩きが通る。測る量: 経路の語に基盤の名札が付く割合、正解の語が付いた名札の分布。
3. **同点の解消**: 今の鍵で同点だった並びが、作成者の比率で分かれる。測る量: max_class で止まる十字の数、類の大きさ、順向き・逆向きで同じ類になる割合（§5）。

「基盤を更新することでも能力向上」（L3-11）は、U_F・r_F を変えて同じデータで作り直すことに当たる。基盤の仕様は sha で版を持ち（§4）、結果は版ごとに比べる。

### 3.2 (b) 未知語のための粒度の接続

**定義**: 段 T で問いの内容語 u が空間に無い（n_T(u)=0）とき u を T の未知語と呼ぶ。今は L-52 によりエネルギー 0・共有なし・何も起きない（問いの十字の腕の外端が空く）。§2.4 (4): RUN で 139 語、94 問中 74 問。

**代役（stand-in）**【推奨】: 未知語 u の、より細かい段の部品のうち空間にあるものを通して、u の段の単位を代わりに立てる。

```
parts_W(u)   = u を WORD の区切りで切った内容語のうち、WORD の空間にあるもの
standins_T(u) = 段 T の単位 v のうち、ある文で v の span が parts_W(u) のどれかの出現の span を含むもの
               （F2 の SpanIndex、L-480 の span の包含。文字列の部分一致ではない）
```

- 代役は問いの側の置き換え【推奨・L-G1-8】: (1) 読む十字を選ぶとき（V1 `query_crosses`）は、代役を問いの語の集合に加える。(2) 腕の外端に付けるとき（I-07）は、`three_ratios(attached=…)` が 1 断面に 1 語なので、代役 s ごとに「u の場所に s を置いた問い」を別に読み、結果を和集合にして各結果に s と出所を付ける。別の問いの数（代役の数の積）は必ず出力に出す。数が大きすぎる点は OP-G1-7 の範囲で絞る。
- 代役は**粒度から導いた**（`granularity-derived`）印を持ち、u・部品・段・sid・span を出所として残す。代役だけで届いた答えは `via_standin` と印を付ける。代役は u の証拠ではない（u は空間に無い）。
- 最小の構成として試す接続の候補: L_RW（RUN の未知語 ← WORD の部品）、L_RC（RUN ← CHAR の部品）、L_WC（WORD ← CHAR の部品）。§2.4 (5) では L_RW で 139 中 92 語に代役が立ち、証拠の文が RUN の問いの語を含まない 19 問中 16 問で代役が証拠の文に入る。
- 代役の数は中央値 3・p90 132・最大 151（「数」「年」のような 1 字の部品が多くの単位に含まれる）。上限は設けず（N-20）、件数を出し、偶然の当たりの対照（F2 の L-492 と同じく、他の問いの正解が当たる率）を必ず並べる。範囲を絞る読みは OP-G1-7。
- 基盤との関係: 問いの未知語の直後に助詞 p があれば（例「別名は」）、その助詞は基盤の語として既に十字にある。代役が付く腕を p の腕にする読みは OP-G1-8 (b) と同じ点。
- F2（正解が複数の単位にまたがる、18/69）は答えの側の組み立てで、そのまま層 0 で使う（F2 後の決定）。代役は問いの側、F2 は答えの側で、重ならない。
- 層は F2 後の決定に合わせて層 0 だけから始める（代役が層の候補の出所を広げすぎないか確かめてから広げる）。

### 3.3 (c) 利用者の使い方で方向を制御する

決定論的で記録に残り、重み（学習された数）を持たないこと。

**推奨【OP-G1-6 (a)】: M-4 の内側で、記憶が同じ基盤で育つ**
1. 利用者が一覧から選んだ答えは、今までどおり記憶の層に「採用した答え」（N-17）として追記する（追記専用、`kind = memory_answer`）。
2. 記憶の空間（N-16）も同じ基盤 F で十字を作る（R2）。選ばれた答えの文がデータとして基盤の腕に座るので、利用者がよく選ぶ関係の腕に記憶が育つ。
3. **選択の台帳**: 選択ごとに {問い, 選んだ候補, その経路の関係の名札, 基盤の版の sha, 状態の版} を 1 行追記する（N-17「探索の状態」の一部）。台帳から数えるのは整数の数（名札ごとの選択の回数）だけで、表示（どの関係が選ばれてきたか）と推論の量（M-2）で読む順にだけ使う。勝者は決めない。
4. 基盤の比率 r_F は変えない（M-4「基礎の配置は変えない」）。

別の読み（OP-G1-6 (b)）: 台帳の名札ごとの回数で、利用者ごとの基盤の比率を記録された規則で作り直す（例: 順位を選択の回数の順に並べ直し、比率の表 (a) を当て直す）。基盤は利用者ごとに版を持つ。これは M-4 を変える。
別の読み（OP-G1-6 (c)）: 選択で変えるのは問いの付け方（OP-G1-8 (b) の助詞→腕の対応）だけ。

### 3.4 (d) 最小の基盤を探す手順

目的: 「最小限の初期配置で動かす」「最小構成を探す」。

1. **最大の候補** F_max = P12（中心は種、12 席。OP-G1-2 (b) なら P13 の 13 席）＋接続 {L_RW, L_RC, L_WC}＋比率の表（OP-G1-3 の答え）。
2. **測る量**: 内側の繰り返しでは reach（f1/reach.py の定義: 問いの語を持つ十字に正解を含む単位が座る）と CPU 秒だけ。問いの周期（ask）の量（正解が候補に入る数、unans の単独の誤答）は費用が大きい（T9 の rerun_ask は bank2 標準で 2587 秒・4 並列）ので、最後に残った基盤・F_max・基盤なし・P7 の 4 つでだけ測る。
3. **1 つずつ外す**: 決まった順（比率の小さい語から＝外側の環から、語を全て試した後に接続を L_WC→L_RC→L_RW の順）に 1 要素を外して作り直す。reach が下がらなければ外したまま進む（接続は配置を変えないので、接続の除去は問いの側の reach（代役を含めた問いの語を持つ十字）で判定する）。1 巡して何も外せなければ止まる（1 要素の除去に対して極小。全ての部分集合の最小ではない、と報告に明記）。
4. **費用**: 1 回の評価に RUN の十字 約 1859 本（§2.4 (6)）、ordered の RUN 全体が 3281 CPU 秒（f1/summary.md）なので約 1700 CPU 秒（基盤による増減は未測定）。12 語＋3 接続で 1 巡 15 回 ≈ 25,000 CPU 秒、巡は最大 15 なので最悪 約 38 万 CPU 秒。**Air で RUN の段だけ**で回し、1 巡ごとに結果を pull して設計役が続けるか判断する。WORD は最後に残った基盤で 1 回だけ。ask の 4 系は別に、1 系あたり T9 の rerun と同程度（数千秒）。
5. **過学習の確認**: 最小化は bank2 で決めるが、オーナーの原則（固定の問題での点数は目標でない）に従い、残った基盤と F_max と基盤なしの 3 つを、未知の能力の問題集（§5.5）と S300 の T0 90 問でも測って並べる。bank2 でだけ良くなる基盤は「最小」と呼ばない（報告で分けて示す）。
