# LINE3_PUBLIC_DESIGN — 公開版の設計：空から始める記憶と、十字の構造の出番を含む形

設計: Opus（2026-10-13）。実装: Sonnet / Haiku、held-out の問題集と金の答え: codex（Vera のコードを見ない）、審査: Opus。
意味の未決はすべて §9 の問い（OP-PUB-n、推奨を先頭）でオーナーに聞き、答えを `ops/decisions/2026-10-06_line3_faithful_build.md` に逐語で残す。

## 0. 結論（先に）

1. 今の成果（不可答で誤答 0 など）は、ほぼ**文法層と「引用のみ」の制約**から来ている。記憶モードの十字は「1 文を織った小さな十字」で、十字の幾何が働くのは
   REVERSAL（入替の安定）だけ、その精度は 4.2 %。ソブリン・巣（layer 1）・スライド・積みは記憶モードで**使われていない**（§2.2）。
2. 記憶の計器 v1 で構造が平文ログに負けた主因は、(a) 物語が短く、平文ログを全部読めた（構造が勝てる「文脈に収まらない」状況を測っていない）、
   (b) 想起が文字列の言い方に縛られた（「障害訓練はどこで」→ 記憶は「障害訓練の開催地は大阪」）、(c) 主題の二重前置などの不具合（MEM-fix で修正済み）。
3. この設計は、オーナーの既存の言葉（ソブリン、両替機とタンク、巣、スライド、積み、初期配置）を**記憶の索引そのもの**として組む。
   文が入るたびに、文法層が形を見分け（両替機）、形ごとのソブリン（タンク）の十字に**出所つきで**席を足す。中心の語ごとに 1 つの十字が育ち、
   腕は助詞、席は語と出所。主題は巣（十字を詰める上の十字）、時間はスライド、セッションは凍結した積みの 1 段。
   矛盾・入替・更新・列挙は**十字の上で直接**見つかり、想起は十字を辿る（全文を読み返さない）。出力は従来どおり門を通る引用だけ。
4. 「構造でなければできない」を主張するための計器: **全 arm に同じ 1 ターンの文脈予算**を課し、ログが予算に収まらない長さの物語で、
   構造 arm・平文ログ＋検索 arm・**十字の幾何を外した平らな表 arm**（同じ両替機と出所、巣・スライド・安定の鍵なし）を比べる。
   平らな表に勝てなければ「十字の幾何が効いた」とは書かない（§6、事前登録）。
5. 公開の前提として出力の門も直す。未見の bank6 で、v2 の門自体が答えのない問いを 34 問中 2 問通す（「隣駅の」番号）と分かった（§2.3）。
   門 v4 と新しい未見の bank7 で 0 を確かめるまで、README は「誤答 0」を無条件には書かない。

## 4. 形

### 4.1 全体の流れ

```
モデルの文 / 利用者の文
   │ write
   ▼
両替機（文法層: 節を切り、形を見分ける）── 形に入らない ──▶ 拒否（形の検知、言い直し）→ なお残すなら「形なし」のタンク（OP-PUB-2）
   │ 形ごと
   ▼
タンク＝形ごとのソブリン（属性・出来事・主題値 …）
   │ 中心の語の十字に席を足す（出所 sid・ターン・記録/構成の印）。凍結、捨てない
   ▼
記憶の十字（中心 1 語に 1 つ。腕＝助詞（の に で と を が）、中心の関係＝は、席＝語＋出所）
   │                     │                      │
   ▼                     ▼                      ▼
巣（layer 1: 主題の十字が属性の十字を詰める）  スライド（文 N → N+1: 時間の順）  積み（セッション 1 つ＝凍結した 1 段）
   │
   ▼
検知（十字の上で直接: 同席異値・入替・更新・列挙）── 注記として返す（書き込みは止めない: L-MEM-09）
想起（問い → 両替機 → 十字を辿る → 席の出所の文）
   │
   ▼
出力の門（引用のみ、v4）→ emit / abstain → 台帳（ハッシュ連鎖、再生）
```

新しい部品は「両替機」「タンク」「記憶の十字」「巣」「スライドの順」「十字の上の検知と想起」「十字の窓（モデルに見せる形）」。
既存の部品（文法層、門、鍵、台帳、凍結、強制の 4 層）は変えない。旧版（mem.v1〜v3）の台帳はその版で再生する。新しい版は `mem.v4`。

### 4.2 両替機：形の見分け（決定的、文法層だけ）

入力の各節を、文法層の切り方で次の形に振り分ける。形は「初期配置」の一部（固定の表、sha で凍結）。

| 形 | 節の型 | 中心 | 腕の席 | 中心の関係（は）の席 |
|---|---|---|---|---|
| F1 属性 | 「X の Y は A」 | Y | の: X | A（値） |
| F2 主題値 | 「X は A」（X が名詞、A が名詞句・数） | X | — | A |
| F3 出来事 | 「X が Y を V」「X が Y に V」「X で V」… | V（述語の語幹。OP-RE-1 により活用形は頭にしない: 語幹は文法層の切り方のまま） | が: X、を: Y、に/で/と: … | — |
| F4 主語なし | 主語のない節 | 宣言中の主題の巣に入れる（§4.4） | 節のとおり | 節のとおり |
| F0 形なし | 上のどれでもない（並列の格助詞、助詞でない隙間など） | 入れない | — | — |

F0 は今の `span_inexpressible` と同じ判定で、形の検知（OP-MEM-3 (a)）として記録する。両替機の判定は台帳の行に `shape` として残す。

### 4.3 記憶の十字（タンクの中身）

- **1 つの中心語に 1 つの十字**（タンクごと）。中心は文法層の WORD 単位。6 本の腕は基盤と同じ助詞（の に で と を が）を梯子の順に持ち、中心の関係「は」が値の席。
  つまり**基盤の十字（初期配置）が、そのまま記憶の十字の型**になる。
- **席**: 語の単位 + 出所 `(sid, turn, session, origin)`。origin = record（履歴にあった語）/ constructed（モデルが初めて持ち込んだ語）。
- **忠実**: 席は捨てない。腕の席が増えたら外側の輪を足す（L を増やす。既存の「L が増えると外側に空の輪を足す」と同じ）。予算で閉じることはしない（stack.py との違い）。
- **腕の中の順**: 席は鍵 (n,p,a) で並べる（n, p は記憶の履歴の共起と語順、a は付着）。同点は出所の早い順。読む順は OP-LOOM-3（が・を・と・で・に・の → 中心）。
  これが十字の幾何が想起の順を決める箇所。
- **凍結**: 置いた席は動かない（D-5）。取り消しはしない。supersede は「新しい席が古い席を上書きした」という印を足すだけ（履歴は残す）。
- 十字は H（文の列）と台帳からの純関数で、いつでも作り直せる。真実として保存はしない（M₀ の原則）。

### 4.4 巣（layer 1）：主題

- `declare_topic(X)` は、X を中心とする**巣**（上の十字）を開く。巣の席は「X について書かれた十字」（X が の の腕にいる十字、X が中心の十字、F4 の十字）。
- F4（主語のない節）は文字列に主題を前置しない（mem.v3 の前置をやめる）。節をそのまま十字にし、その十字を**今開いている巣の席**に置く。
  これで「主題の二重前置」は形として起きない。主題に助詞が入っていても（「A社のB事業」）、巣の中心が「B事業」、その の の腕に「A社」となるだけで、拒否は要らない（OP-PUB-3）。
- 主語のない問い（「広報の締め切りは？」を巣「新製品」の中で聞く）は、巣を辿って答える。巣を経由した答えは `via: nest` を記録する（OP-PUB-4）。

### 4.5 スライド：時間の順

- 文 N の十字から文 N+1 の十字へ順の辺を張る（既存のスライドするソブリンの考え方: 窓は前の文の終わりから始まる）。
- 「更新」= 同じ席の位置（中心・腕の道・値の席）に、後の文が別の値を置いたこと。「後」はスライドの順で決まり、時計は使わない。
- 物語の中の「AからBに変更」は F1/F3 の節として入り、スライドの順で後の値が新しい値になる。

### 4.6 検知：十字の上で直接

| 検知 | 定義（十字の上） | 数えるか |
|---|---|---|
| 同席異値（矛盾） | 1 つの十字の同じ席の位置（中心・同じ腕の道・値の席）に、異なる文から異なる値が 2 つ以上あり、後の値が supersede の印を持たない | 数える |
| 更新 | 同席異値のうち、後の文が「変更」の形（変更・から…に）を持つか、モデルが supersede した | 別の列（矛盾ではない） |
| 入替 | 2 つの語の組が、ある文では が/を（または の の向き）で一方、別の文では逆の腕にいる。判定は既存の鍵の入替（centre↔arm の swap が (n,p) を改善するか）を、**集約した十字**の上で行う | 数える |
| 列挙 | 同じ中心・同じ値の席に別の値があるが、の の腕の席（X）が違う（認証の期限 / 決済の期限） | 数えない。矛盾と区別される（今の CONFLICT/arm の誤報の原因を形で消す） |
| 形なし | F0 | 形の検知（コスト列） |
| SAME_QUESTION | 今の門を履歴に当てる自問（mem.v3） | **第 2 の証人**として残す。十字の検知と一致したかを報告 |

構造の拒否（形なし）と構造の注記（同席異値・入替）が経路 (1)、モデルの `report` が経路 (2)。両方を台帳に残し、計器で別々に数える。

### 4.7 想起：十字を辿る

1. 問いを両替機に通す。「X の Y は何」→ (中心 Y, の: X, 値の席)。「X は何」→ (中心 X, 値の席)。「X はどこで V」→ (中心 V, が/は: X, で の席)。
2. **問い語のタンク**（初期配置の薄い語彙、凍結）: どこ ↔ 場所・開催地・会場・所在地、いつ ↔ 日・日時・期限・締切、誰 ↔ 担当・責任者、いくつ・何人 ↔ 数・人数、など
   数十語。「障害訓練はどこで」→ 中心 障害訓練 の の の腕にいる 開催地 の十字の値、を辿れる。表は §8 M6 で codex の金とは独立に作り、sha で凍結する。
3. 表に無い橋は**モデルが補う**（`bridge(問いの語, 記憶の語)`、構成の印つきで台帳に残る）。構造に語が無いときモデルが補う、という構想の形。
4. 見つかった席の**出所の文**から、門が引用を判定する（v4）。答えの値は必ず記憶の文の一部分。
5. 結果: ANSWER（1 値）/ CHOICE（同席異値、出所 2 つ以上）/ UPDATED（最新の値 + 履歴）/ NONE。

### 4.8 十字の窓：モデルに見せる形（文脈の拡張）

- 書き込みの結果は、十字の JSON 全体ではなく、**変わった席と注記だけ**の短い行で返す（計器 v1 の費用の主因は十字の JSON が会話に積まれたこと）。
- `view(中心)` / `view_nest(主題)` は、その十字（または巣）の席を出所つきで、固定の上限（例: 40 行）で返す。全文のログはモデルに渡さない。
- 1 ターンにモデルが受け取る文字数の上限を、全 arm で同じにする（§6、OP-PUB-5）。

### 4.9 成長：積み

- セッション 1 つが凍結した 1 段。段ごとに数える: 十字の数、席の数、巣の数、同席異値・入替・更新・形なしの数。
- 固定の問い（held-out）を段ごとに当て、G4 の「現れる・残る・壊れる」を記録する（記憶の設計 §4.7 の 3×3 表をそのまま使う）。
- 成長の主張は「段を重ねるほど現れるが増え、壊れるは仕掛けた矛盾・更新でだけ起きる」（P4）。

### 4.10 十字の幾何が効く所・効かない所（正直に）

| 機能 | 平らな表（中心・助詞・値・出所）でもできるか | 幾何が足すもの |
|---|---|---|
| 同席異値・列挙の区別 | できる（索引の機能） | なし。ここは「索引としての十字」 |
| 想起の順・同点の分け方 | 出所順ならできる | 鍵 (n,p,a) による順（どの席を先に読むか） |
| 入替 | 組の向きを比べればできる | 集約した十字の swap の安定で、1 回の書き込みでなく履歴全体の向きと比べる |
| 主題の巣 | 主題の列でできる | 巣の中の十字の詰め方（どの十字が主題に属するかを の の腕の連鎖で決める） |
| 更新の順 | 時刻順でできる | スライドの窓の連なり |

十字の幾何が「なくてはならない」と言えるのは、P3 で平らな表に勝ったときだけ。勝てなければ §6.6 の周回で構造を見直す（OP-PUB-8 の変更）。

## 5. 出力の門 v4

- v3 の安全な集合から R7（命名の動詞「いう」）を外す（オーナーの決定どおり）。
- 主語の修飾語: 問いの主語が「X の Y の」の連鎖（「隣駅の番号」）のとき、連鎖の**すべての名詞**が節にあることを要求する（B6-U35/U36 の型）。v2 の門も同じ穴を持つので、v4 は v2 の後継として作る。
- 凍結の手順は v3 と同じ（ソースの sha と規則の digest を、未見の問題集を読む前に記録）。
- **bank7**: codex が新しく作る未見の問題集（可答 30 + 不可答 40、形の偏りなし、bank6 の S1〜S7 の型を含む）。v4 は bank7 で 1 回だけ探針し、規則を変えたら v5 と bank8。
- 既定の切り替え: v4 が bank7 で不可答の通過 0 なら、v4 を既定にする（OP-PUB-6）。

## 6. 計器 v2：長い物語

### 6.1 物語（codex、held-out、モデルは見ない）

- 6 本。1 本 600〜1000 文、10〜20 セッションに分かれた作業ログ風の話（会議、仕様、担当、締切、場所、変更）。
- 仕掛け: 矛盾 12、入替 4、更新 8、列挙の罠 8、繰り返し 6、主語のない文の割合 30 % 以上、言い方を変えた問い（融合した slot）を問いの半分以上。
- 問い: セッションの区切りごとに 10 問（present / contested / updated / absent）。金は codex。

### 6.2 腕（同じモデル、同じターン数、同じ `report`、**同じ 1 ターン予算**）

| arm | 記憶 | 想起の道具 |
|---|---|---|
| A0 文脈のみ | 直近の会話だけ（予算内） | なし |
| A1 平文ログ＋検索 | 全文を追記するログ | `log_grep`（語で検索、上限行数）、`log_read(範囲)` |
| A3 構造（この設計） | 記憶の十字・巣・スライド・積み | `recall`、`view`、`view_nest`、`bridge`、注記 |
| A3f 平らな表（幾何なし） | 同じ両替機と出所の表（中心・助詞・値・sid） | 表の検索。巣・スライドの順・鍵の順・swap の入替はなし（入替は組の向きの比較） |

予算: 1 ターンでモデルに返す道具の結果の合計を固定の文字数（例: 6000 字）で切る（OP-PUB-5）。物語全文はどの arm でも予算を大きく超える。

### 6.3 測るもの

矛盾の発見（構造の注記 / モデルの report の別）、入替、更新を最新値で答えた数、列挙の誤報、回答の正解・過広・棄権・確信誤答、成長の「現れる・残る・壊れる」、
入力トークン、ターン数、1 回の暴走（同じ道具の連続呼び出し上限、§8 H1）。反復 3 回、平均と最小–最大。

### 6.4 事前登録の予測（外れたら外れたと書く）

- P-PUB-1: 予算の下で A1 の回答の正解は計器 v1 の 55/60 から大きく落ちる（検索が言い方に縛られる）。
- P-PUB-2: A3 は A1 より矛盾の発見が多い（十字の上の同席異値は全履歴を見る。A1 は検索に当たった範囲しか見ない）。
- P-PUB-3: A3 と A3f の差は、同席異値・列挙ではほぼ 0、入替と更新の順で A3 が上。差が出なければ P3 は落ちる。
- P-PUB-4: A3 の入力トークンは A1 と同程度以下（十字の窓が短いため）。

### 6.5 費用の見積もり

門 v2 の再計測の実績（入力 6,280 万トークンで約 6.4 ドル）の比率で、計器 v1（入力 9,245 万）は約 9〜10 ドル相当。
長い物語は 1 run あたりのターンが約 3〜4 倍、arm は 4、物語 6 × 3 回で、約 40〜80 ドルと見積もる。月の API クレジット（200 ドル）の範囲。暴走の上限（§8 H1）を先に入れる。

### 6.6 見直しの周回（OP-PUB-8 の変更、オーナー 2026-10-13）

P2・P3 の両方を満たすまで公開しない。落ちたら次の周回に入る。

1. **物語の分け方**: codex に物語を「開発用」と「判定用」に分けて書かせる。開発用（2 本）は原因の調査に何度使ってもよい。判定用（6 本 1 組）は**1 組を 1 回だけ**使う。
2. **周回 k**: (a) 判定用の結果と開発用の物語で負けた原因を調べる（どの検知・想起で落ちたか、平らな表と何が同じだったか）。(b) 構造の見直しを設計し、意味の点はオーナーに問う。
   (c) 実装して mem.v4+k として凍結（ソースの sha と形の表・問い語の表の sha を、次の判定用の物語を読む前に記録）。(d) まだ一度も使っていない判定用の組で測る。
3. **判定**: P2 と P3 の両方が、反復の範囲が重ならずに満たされたら公開へ。どちらかが落ちたら周回 k+1。
4. **記録**: 周回ごとに、何を変えたか、どの組で測ったか、結果を報告に残す。負けた周回の結果も消さず、公開時の README に「何周目で満たしたか」を書く。
5. **費用**: 1 周の計測は約 40〜80 ドル（§6.5）。月のクレジットの半分を超えそうな周回の前にはオーナーに知らせる。
6. **合わせ込みの監視**: 判定用の組の物語・問いの文面を、見直しの設計者も実装者も読まない（報告の数字と型だけを見る）。読んだ組はその後の判定に使わない。

## 10. 却下した案

- stack.py の十字（共起の幾何、予算で閉じる）をそのまま記憶の索引にする: 閉じた後の語が `left` に落ち、出所が失われる。G-2 で 65.6 % が誕生時に閉じた。
- 同席異値で書き込みを止める: モデルが矛盾を言い換えで隠すことを覚える（記憶の設計 §8 と同じ理由）。
- 平文ログ arm から検索を外す: 不公平で、勝っても主張にならない。
- 学習済みの埋め込みで想起の言い方を吸収する: 「学習不要」に反する。橋は問い語のタンクとモデルの `bridge` で作る。

## 11. いちばん大きい危険

- **両替機の形の取りこぼし**: 自然な日本語の多くが F1〜F4 に入らないと、計器 v1 の「書き込みの 30 % 拒否」が繰り返される。M1 の後、長い物語の文で形の当たり率を先に測り、
  70 % を下回れば形を足す（意味の判断はオーナー）。
- **P3 が落ちる可能性は高い**: 同席異値と列挙は索引の機能なので、幾何の差は入替と順に限られる。落ちたら §6.6 の周回で、幾何が効く機能（入替・巣・順）を強める見直しをする。
- **周回での合わせ込み**: 直しては測るを繰り返すと、構造が物語に合ってしまう。§6.6 の 1 組 1 回の規則で防ぐ。
