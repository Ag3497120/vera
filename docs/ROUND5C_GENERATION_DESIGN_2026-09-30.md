## 候補契約 — 原文から最終文まで残す単位

以下はschema候補であり、A/Bの実装型への決定ではない。共通のSourceSpan、entity/event変数、scope、proof参照が利用可能ならadapterで共有する。Aが読めない表現はC固有の語彙分岐で成功扱いにせず、Cの読解不足として残す。一方、gold planから先の診断はAを通さずできるようにする。

| 契約 | 最小の保持内容 |
| --- | --- |
| `BriefSource` | 原文、immutable hash、language、入力した立場、文字位置規約、正規化から原文への写像。 |
| `ConstraintLedger` | obligation ID、原文span群、作用域、対象entity/event/world、要求型、必須/希望、肯否、順序/数量、読解候補、未解決/競合。全内容語・機能語の扱いも追跡する。 |
| `ContentPlan` | ledger hash、world tree、entity台帳、event/claim graph、文・段落/句への配置、照応、視点、時間、終状態、談話関係、対応するobligation、根拠または創作導入の許可、探索履歴。 |
| `ClaimNode` | predicateと型付きrole、polarity、時点/区間、quantifier、world ID、発話/引用speaker、主張態度、evidence、由来mode。文そのものをpayloadにして意味検査を回避しない。 |
| `StateTransition` | 同じworld内の前提、明示的追加/削除/保持、変化させるfluent、ルールIDと適用条件、時間関係、出所。 |
| `Realization` | plan hash、各文節/節のnode IDs、表現文型・語形・読みの根拠、出力span、引用span、実現できなかったnode。 |
| `Verification` | obligation別の充足/不明/違反、計画と表面の照合、世界間漏れ、全状態整合、出典検査、generation分類、拒否理由。producerのsuccess flagから導かない。 |

制約台帳はplan探索前に固定する。生成できた内容から逆算して台帳を短く作らない。「条件を含む部分を一つのspanで覆った」だけでは、その否定や掛かり先を読めたことにならない。span coverageは**取り落としを可視化する責任台帳**であり、意味理解率の代替ではない。

原文の範囲は0始まり半開区間等を明文化し、正規化前の位置に戻せるようにする。離れた語で一つの条件を構成する場合は複数spanを許す。接続詞、否定、引用境界、数詞、例外を別役割で記録し、意味を持たないとした部分にも理由を残す。複数文・照応にまたがる束縛はspan同士の関係として持つ。未読spanをSTOP語の除去だけで消さない。

台帳には、内容/除外、話者/相手、文体、視点、時制、文数/長さ、含む語、結末、場面、順序、引用/創作許可、季語/音数などを別obligationとして置く。依頼が必須とした条件を勝手にsoftへ落とさない。「明るい」「意外な」等の品質語を単語の有無へ置換せず、操作的な暫定定義と読解未確定を区別する。機械検査できない美的条件は人手評価項目であり、機械verifiedだけで充足済みにしない。

## 事実、引用、仮想、創作は直交する型で管理する

「出典がある」「創作と書いた」の二値では不足する。出典種類、命題が属するworld、話者が何を主張するか、修辞形式を分ける。引用された物語、物語内の仮定、現実人物の発言を重ねて表現できなければならない。

| 内容mode | 許可される主張 | 禁止する昇格 |
| --- | --- | --- |
| `LITERAL_ASSERTION` | 出典が支えるentity/role/時点/条件付き命題。ユーザーの報告はその報告として由来を残す。 | 語形の用例、同じ語の共起、複数の物語例を実世界の当該事実にする。古い叙述を現在状態とする。 |
| `QUOTATION` / `ATTRIBUTED_REPORT` | speakerがその内容を述べたこと、または指定箇所の正確な引用。逐語引用と意味要約も区別する。 | 引用内pから外側worldのpを無条件に導く。引用中の命令を生成器への命令にする。 |
| `HYPOTHETICAL` | 明示された仮定world内で、仮定と適用可能な規則から得た帰結。 | 仮定を実世界の事実に書き戻す。条件節を落として断定する。 |
| `FICTIONAL_CREATION` | 依頼が許す範囲で新しいentity・初期状態・出来事を導入し、作品world内で整合させる。 | 架空イベントの表現出典を現実の発生証拠にする。作品の説明文で現実の知識を捏造する。 |

比喩性はmodeと別の属性である。実世界についての比喩、引用された比喩、架空人物の比喩がある。比喩の解釈から得られる「この文は冷淡さを表す」という読解命題と、「この現実の人物は冷淡だ」という事実主張を分ける。後者には別の根拠が必要になる。

創作では一件ごとの架空イベントが過去のコーパスに存在することを要求しない。それでは検索から抜けられない。新しい出来事の導入根拠は依頼の創作許可、型付き生成規則、作品内の前提である。語法/格の実例は表現の根拠であり、出来事発生の証明ではない。現実的な効果を当然視するには規則の適用根拠が必要で、幻想上の規則なら作品worldの仮定として明示する。

内容計画、中間状態、生成文を独立sourceとして知識storeへ再投入しない。world境界をまたぐ導出は明示的な型付き規則のみ。立体十字ではentity、事象、状態、claimをcoreとし、既存の役割・面・辺を保持する。粗い段落計画には細かい節の参照を持たせ、粒度を上げた際に元のobligationを消さない。各sovereignの候補と根拠は独立のまま受け渡し、異なるfamilyの頻度・類似度を足して一つの確信値にしない。

## 計画を出力へ因果的に接続する実装の核心

1. raw briefを読んで台帳を固定し、候補を独立sovereignから取得する。検索候補は完成回答でなく、型付き命題、語彙/文型、比喩対応、音の候補として受け取る。
2. boundedな制約探索でContentPlanを作る。候補文を後から整列するのでなく、必要な出来事・関係・終状態を満たすplanを先に検査する。初期状態、利用規則、entity identity、worldを確定せず検索文を接ぐことは認めない。
3. realizerへ渡す意味入力は検査済みplanのみ。出典の完成文は逐語引用nodeにだけ許す。通常の文実現はplanのrole/時制/態/修辞と語形・文型から構成する。raw briefを別途読んで取りこぼしを隠す第二の生成器にしない。
4. outputの各主張節はplan nodeへ対応させ、必須nodeの未実現と余分な主張を両方検査する。計画で認めた内容以外を接続詞や形容詞で足すことも余分な主張になる。修辞上意味を持たない表現差は別扱いにできる。
5. 関係の型から接続詞を選ぶ。Before、Cause、Contrast、Elaboration等を区別し、二文が近いだけで「だから」「すると」を付けない。`connective_render.py:129–152`の候補は利用できるが、関係の成立根拠はCが渡す。
6. verifierが台帳・plan・出力・出典を検査して初めて公開ANSWER/CREATEDを返す。plan failureを旧検索生成へ黙ってfallbackしない。引用/検索結果を別種の回答として返す場合も、依頼に対する未達を残す。

実装後の因果接続検査では候補在庫と表現資源を固定し、planの参加者、終状態、順序、否定、視点、時制、転移属性、冗談の第二義を一箇所ずつ変更する。対応する出力が変わるかtyped拒否になり、無関係な要求は保持されることを別検査器で確かめる。意味の異なるplanを入れても検索済み文列がそのまま出るならCは未実装と判定する。

plan nodeの削除、obligation IDの偽造、根拠の差替え、引用worldの変更も拒否試験にする。traceの表示文だけの変更は回答を変えてはならない。plan hashをtraceへ書いた事実だけでは合格させない。データ依存のコード監査とこの介入試験を併用する。

## 複数文の状態、照応、視点、時制

entityは表示名と別のIDを持つ。同じ名前・同じ場面であることだけで別sourceの人物を併合しない。source内の同一性証拠、明示的なbrief指定、承認済み束縛で接続する。代名詞と省略主語は型、役割、談話上の到達範囲から候補を作り、複数残ればREFERENT_AMBIGUOUSとする。「直前に出た名詞」を最終oracleにしない。

状態はworld/entity/time/fluentごとの真、明示的偽、不明、競合を区別する。排他的な所有・位置・開閉等も、そのfluentの型で排他性が定義される場合だけ検査する。記述されないことを偽にせず、継続は持続可能と定義したfluentと区間に限定する。イベントに前提、変更、保持範囲を持たせ、登場人物の持ち物や位置が理由なく戻ることを防ぐ。イベントの全述語へ一律の慣性を付けない。

時間はイベント順の部分順序と時点/区間を持ち、叙述順と発生順を分ける。回想は別の時間参照を使う。現在/過去の表面活用だけでなく、誰の「いま」か、叙述時点、継続/完了、引用内の時点を保持する。既存Frame keyで確認できない時間特徴を独立検査の対象にする。

視点にはnarrator、focal entity、知覚/発話/伝聞により到達できる情報を持たせる。限定視点の人物が他人の内心を断定するplanは、explicitな伝達か許可された全知視点がなければ拒否する。人物が知らないことと世界で偽であることは別である。Kripkeの有限完全モデル検査を用いる場合は、その世界集合・命題集合の完備性を明示した局所検査に限る。

状態検査だけでは「よい物語」は得られない。目標、障害、選択、結果、語りの焦点を内容計画へ持たせる探索は別に必要であり、ここは未解決の品質課題を含む。まず短い物語でも結末制約と中間状態を同時に満たせるかを反証し、長文化で同じ整合が維持できるかを後段で検証する。

## 常識を使う境界と、不足時のtyped拒否

常識ruleは、前提role、適用条件/例外、結果、時間、強さ（観測例/傾向/必然等）、出典、適用worldを持つ候補とする。複数の後続場面を数えただけで必然や確率に変えない。既存条件例の取得は観測例として再利用する。助言には、目的との一致、行為の効果、必要な条件の成立を別に要求する。目的が違う事例や失敗例を成功手順へ混ぜない。

推論は登録されたルールとその前提の結合をboundedに探索し、存在しない世界知識を「普通なら」で補わない。創作world内で新しい初期状態を作者として置くことと、現実の因果を推定することを別操作にする。局所的に自己完結した創作は、現実の全常識がないことだけを理由に一律停止させない。

| 拒否型候補 | 具体的に示す不足 |
| --- | --- |
| `BRIEF_CONSTRAINT_UNREAD` / `BRIEF_CONSTRAINT_CONFLICT` | 原文の読めないspan、または両立しないobligation。検索量不足とは区別する。 |
| `WORLD_EVIDENCE_MISSING` / `RULE_SCOPE_UNKNOWN` | 不足する命題、時点、適用前提、例外。出典が多いだけでは解消しない。 |
| `STATE_CONFLICT` / `REFERENT_AMBIGUOUS` / `VIEWPOINT_UNSUPPORTED` | 衝突する状態、候補entity、視点から到達できない内容。 |
| `FIGURATIVE_MAPPING_MISSING` / `FIGURATIVE_MAPPING_TIED` | 対応役割・転移属性の不足または同点。 |
| `HUMOR_READINGS_UNSUPPORTED` / `METER_READING_AMBIGUOUS` | 第二義の根拠や語の読みが未確定。 |
| `PLAN_BUDGET_EXHAUSTED` / `REALIZATION_UNVERIFIED` / `NOVEL_PLAN_UNAVAILABLE` | 探索予算、表現可能性、新規計画の不足を区別する。未発見を不存在の証明にしない。 |

拒否時は満たせなかった型と原文範囲を返す。何でも「コーパスを増やしてください」にしない。部分草稿を出すなら依頼が許す範囲で未達条件を明示し、全条件達成の成功数には入れない。

## 比喩 — 属性の共通部分から、対応役割と限定転移へ

候補`MetaphorPlan`は、target/sourceのentityまたは関係構造、対応するroleの写像、選んだtransfer property、転移を許す根拠、転移しない属性、解釈のworld、原文spanを持つ。単語二つを並べて共有属性を取るだけでなく、何が何に対応し、どの関係が保たれたかを残す。

`figurative`とAbilitiesのproperty候補を入力に使い、役割の反転や型不一致を検査する。sourceの物理的属性をすべてtargetへ輸入しない。字義的な類例の存在、比喩的用例、当該発言の文脈による意図の候補を区別する。既存profileは比喩用例が混じると字義の証拠を汚し得るため、mode別の由来が必要になる。

解釈では、targetにその属性が現実にあるという独立証拠がないことだけで「この表現がその属性を示唆する」という読解まで拒否する必要はない。ただし複数の解釈が残る場合は同点拒否し、現実の属性断定へは進めない。生成ではbriefが指定したtransfer propertyと伝えたい態度をplanに持ち、表現だけから事後的に意図を作らない。

検証はmapping role交換、転移属性差替え、非転移属性の混入、target/source交換、字義と比喩worldの交換を含む。属性語の有無のみで合格しない。長い慣用比喩、文化的連想、新規関係比喩の妥当性は未解決であり、有限のproperty追加だけで一般比喩理解を達成したとは扱わない。

## 冗談 — 音の一致と意味転換を別々に検査する

候補`HumorPlan`はsurface/readings、二つ以上のsense/role構造、setupが支持する読み、pivot、punchlineが可能にする別の読み、両方の語法根拠を持つ。音の一致を使う場合は既存kana/同音語部品を再利用する。二つの字形を同じ読みで置換しただけで意味転換成立とはしない。

最初の実装は、根拠のある複数の読みと短いsetup/punchlineを結べる範囲で構造検証する。setup内で第二義だけが露出して転換が消える、punchlineが第一義でも同じである、二つの語義の格構造が成立しない候補を区別して落とす。辞書的な語義候補には`sense_split`等の既存部品を使えるが、利用可能なsidecarや語義在庫を確認せず完成済みとみなさない。

構造的な二義性があることと、読者が面白いと感じることは別の評価軸である。後者を同音一致や候補数から算出したverifiedへ置換しない。皮肉、状況的ユーモア、社会的文脈、長い伏線は段階的拡張対象とし、永久に語呂合わせだけへ目標を縮めない。

## 俳句 — 内容、読み、配置を三句で共同探索する

候補`PoemPlan`は三句の内容node、scene/time/viewpoint、中心像、季節・季語の扱い、切れ、語彙/読み候補、音数制約、briefの必須語/除外語を共有する。定型5/7/5や季語は依頼とジャンル契約から決める。自由律や別言語の詩を、日本語の固定規則の不合格として永久拒否する設計にはしない。

探索変数は句ごとの意味、語形、読み、順序、切れ位置である。先頭を固定して残りを貪欲に埋めず、部分planの音数範囲と意味制約から枝刈りし、必要なら先頭句へ戻る。DPまたはbounded backtrackingを既存form/phrase候補の上で行う。読みが複数ある語は詩の文脈で選べた根拠を持ち、17音になる読みを都合よく選ばない。

共同探索の反証は、同じ語句在庫で初期選択を戻さなければ全制約を満たせない構造を独立に作り、貪欲経路との違いを見る。mora関数の検査と、季節/場面/視点/新規内容の検査を別にする。音数を合わせるため内容制約を落とした候補を成功に数えない。既存詩二つの句の入替えは再配置として記録する。

季語辞書、読み、古語、切れの効果、余情等の品質問題は別々に残る。単なる5/7/5成功を俳句能力の完成とは呼ばない。意味が異なる候補の同点を乱数で解消しない。候補複数提示が依頼で許される場合だけ区別して提示できる。確定した同一planの意味を変えない綴りや語形の選択は、意味候補の同点判定と区別する。

## 公開one.Veraにつなぐ最小実装単位と予定箇所

最小のC縦断試作は、rawの短文briefから複数文の制約台帳を作り、少なくとも参加者、肯否、順序、時制/視点、終状態を保持したContentPlanを探索し、既存実現器で全文を出し、独立gateまで通す単位とする。最初の対象構造を事前登録し、未対応構造の拒否を公開結果に含める。文数だけを固定した既存候補文の選択器はこの単位を満たさない。

| 予定箇所（実装はまだしない） | 核心 |
| --- | --- |
| 新規 `content_plan.py`（仮称） | immutableな台帳/世界/命題/状態/談話/特殊計画。A/B共通型とのadapterを作り、意味の異なる型を一つの文字列dictへ押し込まない。 |
| 新規 `content_read.py`（仮称） | 原文spanと作用域を保持してbriefを読む。A候補読解を利用できるが、Cの読解不足と曖昧性を独立に報告する。 |
| 新規 `content_search.py`（仮称） | 必須条件と終状態からのbounded探索、既存source候補/規則のtyped結合、部分planの矛盾検査、厳密な停止状態。 |
| 新規 `content_realize.py`（仮称） | plan→Frame/compose_ja/語形のadapter、mode・時制・視点の表面化、句/節→node対応。引用以外で完成出典文の再生に依存しない。 |
| 新規 `content_verify.py`（仮称） | 原文台帳、plan、出力、根拠を別入力として検査。全必須要求、余分な主張、状態、world、引用、韻律等の独立checker。 |

## 独立評価 — brief読解とgold planを分ける

以下は今後の検証計画であり、本レビューでは問題の作成・実行・測定をしていない。goldは実装reader/plan出力から採取せず、独立担当が原文から作る。創作には正解文が一つとは限らないため、許されるplanの集合、必須/禁止条件、部分順序、world境界、状態関係を主oracleとする。曖昧なbriefを無理に一意goldへ押し込まない。

| 分離トラック | 入力と検査対象 | 隠してはいけない不足 |
| --- | --- | --- |
| R: raw読解 | raw brief → ledger/plan候補。独立の原文注釈と作用域/役割/要求の保存を比較する。 | spanを覆っただけの偽のcoverage、否定/照応/品質要求の取り落とし。 |
| P: 内容計画 | gold ledgerと初期world/規則 → plan。全制約と状態、探索、同点/不足を検査する。 | raw読解能力の評価ではない。コーパス増加だけによる改善と分ける。 |
| G: 文実現 | gold plan → 出力。計画node、時制、視点、mode、韻律の保持を独立検査する。 | gold plan成功を自然文生成成功へ合算しない。 |
| V: verifier | 人手で壊したplan/出力/根拠/台帳を入力し、単一変異の拒否と正しい候補の誤拒否を調べる。 | producerと同じFrame readerの往復検査だけでは検出できない共有誤り。 |
| E: 公開一貫経路 | raw briefのみをone.Veraへ与え、最終出力を独立に評価する。 | gold plan/gold evidenceの注入、評価専用入口、失敗条件の削除、旧経路の再配置成功混入。 |

R/P/Gの一方が成功し他方が失敗した場合、原因をその境界へ戻せる。例えばG成功・R失敗なら表現候補の追加で読解不足を覆わない。Aが成功してもRは独立に必要である。Vでは同じparserの再読を補助に使えても、独立注釈、明示的state simulation、引用span検査、形態/読み検査を異なる契約単位で使う。二つのcheckerが同じ未検証parseを参照していれば独立とは数えない。

変異群は、人物入替え、同名別人、禁止条件の脱落、肯否、世界/引用境界、前後順、持ち物/場所、視点外の知識、過去→現在、比喩role/属性、setup/punchline、mora読み、出典ID、必須node未実現を含める。変異の期待判定を実装checkerに作らせない。同義の許容表現や順序自由な文も入れ、拒否するだけの方式を防ぐ。

## 検索文の再配置を新規生成として数えない

出力ごとに由来を少なくとも `quotation / extractive_selection / reordered_fragments / paraphrase / slot_substitution / new_plan_composition` に分ける。複数混在なら節ごとに分類し、一つの新語で全文をnewへ昇格させない。これは満足度や正答性とは別軸である。引用が適切な依頼では引用を正答にできるが、創作の新規内容合成数へ移さない。

比較器は文字列の長い一致だけでなく、句/文のsource sequence alignment、entityのα変換後の役割graph、出来事の依存/時間関係、templateのslot置換を見比べる。名前や語尾だけの変更、別作品からの序盤と結末の連結、同音語置換はこの検査で別分類にする。既存語彙・文型の再利用自体は妨げず、計画した内容の関係と制約充足の新しさを見る。

`new_plan_composition`は凍結した参照在庫に対する相対的分類であり、人類未発表の独創性を保証しない。全コーパスに同じgraphがないと証明できない場合は、照合範囲と不明を報告する。自分のproducerが「new」と記したflagをoracleにしない。独立担当が由来候補と内容graphを確認し、盲検の作品評価とは分ける。

方式差の比較では語彙/文型/候補在庫と予算を固定し、旧検索/再配置、gold plan+既存realizer、C raw経路を分ける。新しい組合せ・順序・役割・終状態を満たす割合が同じ在庫で増えるかを先に確認する。意味planを壊しても成績が変わらない、または全文計画なしの再配置と変わらないなら、Cの核心仮説を支持しない。

報告は六能力を別々にし、raw end-to-end全必須条件達成率、誤答/棄権、条件別欠落、world漏れ、状態矛盾、自己検査通過/独立不合格、由来分類、plan介入への正しい反応、速度/予算切れを分ける。文体・一貫性・比喩の読み・面白さ・俳句の美的評価には独立人手判断を設け、評定基準と不一致を保存する。機械的整合性と人間の品質を一つの曖昧な平均にしない。

## 実装順序、開発検証、新封印の境界

1. **C0: 契約と検査出口。** 世界/由来/台帳/planの候補型とC移行対象を固定する。旧経路が出した回答にも由来を付け、再配置を隠さない。契約だけで生成能力向上とは言わない。
2. **C1: 全文計画の縦断試作。** raw brief、短い複数文、既存語彙/文型で内容・肯否・順序・時制/視点・終状態を同時に保持する。planへの介入とR/P/G/V/Eの分離を先に通す。A未達ならRの不足を公開したままP/G/Vを診断する。
3. **C2: 物語状態と常識ruleの結合。** entity同一性、明示的前提/効果、照応、仮想/fictionの分離を拡張する。観測例と助言を区別し、結末からの探索と複数文整合を検証する。初期段階の短さを永久的な上限にしない。
4. **C3: 比喩mappingとユーモアplan。** 共通ContentPlan上の別演算として追加する。属性一致と音一致の既存部品を使い、対応役割・限定転移・意味転換をそれぞれ反証する。二領域の成績を混ぜない。
5. **C4: 俳句の共同探索と長文化。** 句単位の意味・読み・韻律探索を全体制約へ接続する。物語/詩の長さ、談話構造、表現言語、文体の範囲を拡大し、全能力の課題を継続する。

開発用の原文と注釈、gold plan、単一変異、形式ルールの出所を分離して保存する。実装者のself fixtureと独立fixtureを区別する。語彙/ルール追加、在庫版、A/B/C各runtime hash、ルート、予算、評価項目、比較条件、合否基準は新封印前に事前登録する。本書は数値合格基準を未測定のまま代用していない。

停止済みの同じ4群へ小修正を施して再試験しない。新封印は開発例と表現・構成・出所を分け、独立担当だけが本文・参照・個別出力を扱う。実装者側への戻りは許可された集計と方式単位の所見に限る。新封印開始後にgold planや失敗文を見てreader/辞書を直し、同じ封印へ戻る運用はしない。公開one.Vera、可用資源、全拒否を含む対象母数を凍結して比較する。

## 実装担当が誤って簡略化しやすい点

1. 完成文列にplan JSONやtraceを付けただけで、planが出力を決めたと呼ばない。
2. 世界modeを応答全体の`created=True`だけへ潰さない。引用内・仮想内・作品内の命題を区別する。
3. 同じ名前、scene、sourceの隣接を、同じentity・因果・状態継続の証拠にしない。
4. Frame再読一致だけで、時制・視点・原文全条件が保存されたとしない。
5. 書けた内容に合わせて制約台帳を後付けしない。span coverageを意味正解率にしない。
6. 創作イベントにも過去の実例を必須にして検索を生成と呼ぶ方式へ戻さない。一方でfictionを現実知識の捏造許可にしない。
7. 観測された行動の後続を、因果・目的達成・一般的助言へ昇格させない。
8. 比喩の共通属性を全属性の転移にせず、語の同音を冗談の意味転換にしない。
9. 俳句の音数合わせのため、場面、季節、視点、必須内容を途中で捨てない。
10. Kripkeの閉世界booleanを未完備の知識へ直接使わない。unknownとfalseを区別する。
11. old round3/Abilities/coreの直接回答経路を残し、Cの拒否をそこで覆さない。
12. gold planの成功、自動検査の成功、原文からの成功、人手の品質、新規性を混ぜない。
13. 同点をソート順・source ID・乱数で破らず、独立sovereignの異種scoreを加算しない。
14. parserの語彙追加だけで全能力を獲得したと報告せず、読解・計画・実現・検査それぞれの未達を残す。

## 未解決研究課題と方式仮説の止め方

自由な日本語briefの否定/省略/作用域、長距離照応、文化的な比喩、ユーモアの期待と意外性、常識規則の範囲/例外、長い物語の価値判断、詩の余情は、小さなparser変更では解決しない。型付き計画は不足の位置を明示し検証可能にする仕組みであり、世界知識や作品品質が自動的に生まれる保証ではない。既存の多言語front-endや別文体も将来のadapter対象として残し、今回の日本語資産の多さを永久的な対象縮小の理由にしない。

最初に反証すべき仮説は、**固定した部品在庫で原文の全制約を保持した新しい内容関係を計画できるか、計画を変えると出力が因果的に追従するか、独立検査が計画/表面/世界/出典の単一破壊を拒否できるか**の三つである。ここが失敗したら語彙数や作品例を増やして成功率だけを押し上げず、R/P/G/Vのどこで失敗したかを改めて設計する。
